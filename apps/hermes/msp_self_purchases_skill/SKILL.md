# МСП Самовыкупы — постоянный первоисточник и порядок работы Hermes

## Когда загружать

При любом вопросе или задаче о самовыкупах, запуске новых карточек, низких продажах, проблемном рейтинге, эффективности прошлых действий, конкурентах, анализе ниши и прогнозировании по этим контекстам.

## ПЕРЕД ответом или разработкой

1. Прочитай `references/PROJECT_COMPASS.md` (актуальный ориентир проекта).
2. Прочитай `references/DECISIONS_AND_DEVIATIONS.md` (позднее утверждённые решения и отклонения от замысла).
3. Прочитай `references/MSP_SELF_01_SOURCE_MATRIX.md` (LIVE_CONFIRMED/CODE_PRESENT/PRIOR_PROBE: не объявляй код работающим API без фактической проверки).
4. Прочитай `references/INITIAL_VISION_V1_2026-10-21.md` (замороженная первоначальная концепция).
5. Если задача требует точной трактовки сказанного на совещании — прочитай `references/MEETING_TRANSCRIPT_2026-10-21.md` (дословная стенограмма).
6. Для технического действия прочитай соответствующую каноническую документацию в `/opt/mcp/projects/msp-server-stack/docs/`; версии и путь должны быть проверены на REMOTE.
7. Если чего-то из указанных источников нет, сообщи **SOURCE_NOT_AVAILABLE**, обозначь пределы анализа и не реконструируй оригинал по памяти.

## Смысл первоисточника

Создать аналитика/прогнозиста: сигнал по SKU → собственные данные → сопоставимые конкуренты (количество, продажи, отзывы, реклама, цена) → экспертный контекст → формулы/экономика → допустимые альтернативы → объяснимая рекомендация → проверка эффекта. История самовыкупов — предмет ретроспективной оценки, её причинный эффект не доказан. Исторические оценки 90/5/5 и 80/20 — не верифицированные коэффициенты.

Всегда отличай FACT, MEETING_ESTIMATE, HYPOTHESIS, MODEL_ESTIMATE, APPROVED_DECISION, UNKNOWN. Не считай один пятизвёздочный отзыв доказательством качества. Не смешивай разные магазины/SKU, плановые и завершённые покупки. Нельзя подменять ожидаемую прибыль выдуманными точными цифрами.

## Действия и безопасность

Это **Skill анализа**, не исполнитель продаж или отзывов. Не создавать фиктивные покупки, искусственные отзывы или инструменты обхода правил маркетплейсов. Изменение цены/остатков/рекламы возможно только через отдельный утверждённый инструмент и разрешённое действие с подтверждением и read-back; данный Skill ничего не меняет. Не изменяй Hermes Gateway, Telegram polling, systemd timers, приватные исходники или текущую SQLite под видом «чтения концепции».

## Контроль направления

Если новая задача расходится с первоначальной идеей, назови пункт расхождения и предложи зафиксировать его в `docs/self-purchases/DECISIONS_AND_DEVIATIONS.md` (только через согласованный процесс изменения GitHub). Не переписывай локальные исторические копии «под текущую версию». Версия установленного Skill должна сопоставляться с проверенным GitHub commit. Для гарантии чтения этой инструкции одного файла в кодовом репозитории недостаточно: требуется отдельная проверенная установка Skill в Hermes и присутствие всех пяти references.
