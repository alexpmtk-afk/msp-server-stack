# История оценок: работающий частичный маршрут 27.10.2026

Источники: официальный MCP tools/list и реальные tools/call. wb_sku(comments) возвращает comments/date/valuation/text и last_request; даты запроса не ограничивают список. В рабочем отчёте только дата/звёзды/признак текста, без текста и персональных данных. Нет доказанной полноты и ID для всех записей.

wb_sku(by_period) возвращает дневные data/rating/comments; daynum=0 — placeholder. Сравнение рейтинга только по точным концам равных окон; отсутствующая оценка и rating=0 дают UNKNOWN. Дополнительно показываются датированные частичные наблюдения и покрытие. Чистая разность comments использует день перед началом окна и его конец; не число новых публикаций.

lk_wb_cabinets(list) доступен. lk_wb_card_table и lk_wb_card_info вернули upstream 403 «Нет доступа» 27.10.2026. Scope не изменялся. Runtime проверяет только таблицу, не выбирая кабинет; даже успешный ответ без проверенного scope/семантики не становится источником четырёх рядов.

Документированные UI ряды всех/негативных оценок и всех/негативных оценок с текстом через проверенные MCP ответы не получены. avg_latest_rating, latest_negative_comments_percent, commentsvaluation не заменяют эти четыре ряда. Универсальный lk_wb_request не использован: документированного отдельного пути с проверенным контрактом четырёх рядов не установлено, обходов 403 нет.

Строгие dated_* модули получают явный UNAVAILABLE и возвращают UNKNOWN; новые достоверные поля без подтверждённого адаптера не выдумываются. Это частичное внедрение наблюдений, не завершённый источник полного числа новых 4–5★.

Собственные события реестра не независимый спрос. Сопоставление найденных записей по близости дат не доказывает происхождение; связь по ID и покрытие источника обязательны для автоматического исключения. quantity — план, не число подтверждённых публикаций.


## Двухсторонний контракт оценок — приоритет текущего уточнения владельца

Три независимых показателя: положительные оценки 4–5★, положительные тексты, общий рейтинг. Для полного расчёта нужен один подтверждённый источник четырёх рядов с одинаковыми карточкой/методикой/типом ряда. Внутренние нормализованные поля ratings_total/ratings_negative/ratings_with_text/ratings_negative_with_text не являются названиями полей MCP; их нельзя заполнять догадками.

Положительные = все − негативные (1–3★); положительные с текстом = все с текстом − негативные с текстом; положительные без текста = положительные − положительные с текстом. compare_dated_rating_periods проверяет ОБА окна; дневные новые показатели суммируются только при наличии всех календарных дат. Для накопительных снимков используются день перед началом и конец каждого окна: результат только чистое изменение, может быть отрицательным из-за удалений/пересчёта. Разница ПОСЛЕ−ДО вычисляется лишь для сопоставимых результатов одного типа. Нельзя смешивать дневные суммы и накопительные разности. Один пропущенный ряд/день не равен нулю.

Существующий CLI автоматически читает comments/by_period в рамках общего лимита 24; пока четыре ряда не предоставлены и не подтверждены, он использует частичный режим. Не считать наличие полного расчётного движка подключением отсутствующего источника. В каждом разделе «ОЦЕНКИ И ОТЗЫВЫ» показывать таблицу ДО/ПОСЛЕ/изменение/полнота. В частичном режиме количество полученных положительных текстовых записей не равно полному числу новых публикаций; разницу этих записей не выдавать за изменение полного количества. Явная фраза: «Полное количество новых положительных оценок не установлено».

Снимки общего рейтинга — точные сопоставимые концы окон, rating=0/NULL не 0★. Дополнительно сохранять даты всех полученных записей, звёзды, has_text и ID при наличии, без текста и персональных данных. Повторы одного ID устраняются, конфликтующие даты/оценки блокируют подсчёт; записи без ID не являются гарантированно разными публикациями/людьми. Даты без записей не заполнять нулями. Действующее правило базового ДО первой даты серии и цензурирования ПОСЛЕ следующей датой сохраняется.

Повторная tools/list-проверка не обнаружила отдельного WB feedback graph tool. Графики count/count_negative/count_with_text/count_negative_with_text найдены в официальной документации Ozon для групп/продавцов; это не принятый контракт WB SKU и не основание для подстановки этих полей в ответы wb_sku. Новые обязательные интеграции не создавались.
