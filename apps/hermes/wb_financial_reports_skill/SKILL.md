# Финансовые отчёты WB: смысл, поиск, сверка

## Когда применять

Вопросы о финансовом отчёте Wildberries: продажи/возвраты, комиссия, к перечислению,
итого к оплате, логистика, хранение, штрафы, удержания, кешбэк, daily/weekly,
поля детализации, полнота скачивания. Не подменяет источник оперативных заказов,
инструкции самовыкупов/рейтингов, банковскую выписку или налоговую методику.

## Практический вход

В `terminal` выполнить:

```bash
msp-wb-report-guide route 'почему перечислили меньше продаж' --json
msp-wb-report-guide field 'К перечислению за товар'
msp-wb-report-guide formula settlement_core
msp-wb-report-guide locate --cabinet wb_novokshenov --year 2026 --type 1
```

Если команды нет в PATH:
`/usr/bin/python3 -I -B /opt/mcp/projects/msp-server-stack/docs/data-sources/wb-financial-reports/guide.py`.
У неё нет HTTP, доступа к токенам или записи в финансовый архив.

## Порядок решения

1. Определить кабинет, период, смысл даты и показатель. `reportType` (основной/выкупы)
   и `period` (daily/weekly) — разные измерения. Выкупы WB не наши самовыкупы.
2. Прочитать единый канон:
   `/opt/mcp/projects/msp-server-stack/docs/data-sources/wb-financial-reports/GUIDE.md`.
   Команда `route` покажет нужные поля и формулы; `field` — определения/варианты названий.
3. Найти выбранное поколение архива через CURRENT и установленный проверенный reader.
   Не складывать все поколения. Не выдумывать финансовую SQL-таблицу.
   Справочник не даёт прав на защищённый архив; использовать разрешённую диагностику.
4. До подсчётов классифицировать операции и определить знаки; сохранить общие расходы
   без SKU. Различать реализацию, перечисление за товар, итог отчёта, выплату и прибыль.
5. Формулы требуют однозначного соответствия реальным полям. `api_binding=NOT_VERIFIED`
   запрещает угадывать имя ключа API. Сначала проверить схему/заголовки конкретной выгрузки.
   Отсутствие сопоставления — ограничение знания, а не нулевая сумма.
6. Считать Decimal в одной валюте. Не вычитать комиссию/эквайринг повторно из перечисления,
   не складывать сводку и её детализацию, daily и weekly за одни даты. Не разносить расходы
   без SKU по товарам без явной методики. Неизвестную коррекцию показать остатком.
7. Для «все отчёты» сверить список каждого ID/типа, терминальную детализацию и публикацию,
   затем покрытие дат по обоим типам. Статус COMPLETE сам по себе не доказательство.
8. Ответить по существу: результат, период/кабинет и существенная неопределённость;
   формулы/поля/источники — когда нужны для проверки или по запросу.

## Ограничения

В исходной статье описана недельная детализация. Наличие локального ежедневного набора
не подтверждено. Техническая карта трёх ключей подтверждена установленным кодом;
остальные API-сопоставления проверять отдельно. Не выдавать расчёт банковской выплаты,
налоговой базы, тарифа или чистой прибыли без необходимых источников.
Семантика не разрешает новый запуск загрузчика/отправку/запись в маркетплейс.

## Проверка результата

`msp-wb-report-guide validate` проверяет связность словаря. Для задачи проверить
реальный источник данных, версию, совпадение показателя и формулы, валюту, знаки,
покрытие и неразобранные остатки. Арифметический пример не равен сверке отчёта.
