### Exact request to gateway (v1)

`POST /api/v1/onec-order-requests`

UTF-8 JSON, exact properties:

```json
{
  "schema_version": 1,
  "request_id": "78189412-5fb7-4e11-ac12-cf33fb7a0b2a",
  "action": "CUSTOMER_ORDER_REQUEST",
  "portal": "b24-uwmjda.bitrix24.ru",
  "portal_member_id": "REAL_VERIFIED_BITRIX_MEMBER_ID",
  "entity_type_id": 2,
  "deal_id": 3,
  "requested_by_user_id": 1,
  "target": "TEST_NEWBASE",
  "created_at_utc": "YYYY-MM-DDTHH:MM:SSZ"
}
```

All IDs above except deal #3 are **illustrative**, not actual user/portal credentials.

Request ID is a new UUID per user-initiated operation and **stable across HTTP retries of that operation**. Do not generate a new UUID for a network retry.

Headers: `Content-Type: application/json`, plus:

- `X-B24-Timestamp`: Unix time in seconds.
- `X-B24-Nonce`: fresh cryptographically random URL-safe string (20–90 chars) for **each HTTP attempt**, even a retry.
- `X-B24-Signature`: lowercase hex HMAC-SHA256.

Signature input (ASCII bytes, using *exact raw request body bytes*):

```text
POST\n/api/v1/onec-order-requests\n<TIMESTAMP>\n<NONCE>\n<hex-lowercase-SHA256-of-raw-request-body>
```

Secret: `B24_GW_APP_HMAC_KEY`, shared only with trusted backend via secure transfer.

HTTP outcomes:
- `202`, `status=QUEUED`: unique command saved durably, **NOT** a 1C order.
- `200`, `status=EXISTING`: request or logical deal already exists, do not resubmit as a new order.
- `400`: invalid request; show an actionable validation failure.
- `401`: signature/clock/nonce error, fail closed.
- `409`: reused nonce or conflicting request ID.
- `503`: persistence failure. **Do not show "sent"**.

GET status: `GET /api/v1/onec-order-requests/{request_id}`, signed with new timestamp and nonce, SHA256 of empty body. Display `QUEUED`, `LEASED`, `RECEIVED_BY_SRV`, or `FAILED_DELIVERY`. `RECEIVED_BY_SRV` means *received by server*, not 1C creation.
