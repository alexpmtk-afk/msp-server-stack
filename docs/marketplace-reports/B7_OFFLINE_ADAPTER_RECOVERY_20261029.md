### Отдельный адаптер versioned_archive.py

- import_csv_versioned — принимает локальный CSV и явно публикует полностью проверенное поколение. WB main/buyout изолированы и требуют правильный reportType. Ozon CURRENT заменяет одну пару файлов, FINAL публикует месячные и годовой отчёты совместно.
- Перед публикацией дважды проверяется отсутствие **legacy CSV/manifest** в области. Если они есть, требуется отдельная миграция; исправные старые файлы не меняются и не переудостоверяются новыми SHA.
- Новое содержимое собирается из закреплённого активного поколения. Под общей блокировкой publish_batch выполняет CAS по ожидаемому родителю. Конкурирующий commit отвергает старый результат; сетевых повторов нет. Неизменившиеся пары сохраняются побайтно.
- read_csv_versioned и verify_versioned_scope читают только подтверждённые и проверенные поколения; ранние закреплённые поколения доступны по generation ID и ожидаемому SHA. Проверка не запускает восстановление. Статус provider_coverage_proven всегда FALSE.
- У CLI появились отдельные команды import-csv-versioned и verify-versioned; прежние import-csv / verify / status остаются только для старого хранения. Старый verify не проверяет новые поколения.

### generation_recovery.py — лишь сохранение следов незавершённой публикации

- quarantine_uncommitted — ручная операция с обязательными точным ID и SHA действующего CURRENT, полным перечнем кандидатов и отдельным подтверждением оператора.
- Под общей блокировкой повторно проверяется CURRENT, хешированная цепочка, CAS и кандидаты. Внелинейные каталоги целиком перемещаются в evidence с синхронизацией каталогов. Никакой пересчёт контрольных сумм повреждённых данных не производится, CURRENT не переключается.
- Повтор после срыва переноса идемпотентен; ошибка между rename и ответом обозначается RecoveryUncertainError. Команда CLI quarantine-uncommitted требует подтверждения.

- При отсутствии/повреждении CURRENT процедура отказывает. Она не выбирает «самый новый» по UUID или времени и не восстанавливает указатель.
