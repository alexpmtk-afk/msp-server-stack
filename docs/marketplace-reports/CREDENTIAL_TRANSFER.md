# Перенос ключей шести кабинетов с Windows на VPS (проект МСП)

Статус 28.10.2026: код подготовки в черновике PR №89; приёмник отдельно перенесён владельцем в `/root/` для проверки без включения сервиса. **Отправка токенов допустима только после завершённой проверки новой версии приёмника; в `main` ничего не сливать без отдельного разрешения.**

## Исходные условия

Владелец подтвердил: все действующие токены WB и Ozon находятся локально на его компьютере, **не на VPS**. Не нужно просить значения в чат, отправлять их через Gmail, Telegram, GitHub или загружать в Google Drive.

В `msp-server-stack` разработаны:
- `scripts/windows/Send-MspMarketplaceTokens.ps1` — локальная Windows PowerShell 5.1 программа с маскированным вводом;
- `scripts/remote/msp_reports_credentials_receiver.py` — серверный приёмник для запуска от root;
- `apps/msp_marketplace_reports/runtime.py` — последующее защищённое чтение реквизитов программой.

Итоговый путь на VPS (после развёртывания):
`/etc/msp-marketplace-reports/cabinets.json` (0600, root-owned).
Создаваемый каталог 0700, root-owned.

## Схема без временного открытого файла

```text
ПК владельца (Windows)
  -> Read-Host -AsSecureString (9 полей)
  -> JSON только в памяти процесса
  -> проверенный OpenSSH канал, stdin
  -> sudo -n python3 receiver.py
  -> root-owned 0600 JSON на VPS
```

Не использовать `ssh -o StrictHostKeyChecking=no`; первый отпечаток узла проверить по доверенному каналу. Не передавать секреты в аргументах команд, в журналах GitHub Actions, подставляя `echo`, или в файлах проекта.

## Подготовка один раз после принятого PR

1. Установить утверждённую версию проекта на VPS отдельной операцией по `docs/MSP_GITHUB_VPS_WORKFLOW.md`.
2. На текущем подготовительном этапе подтверждённый локальный путь приёмника — `/root/msp_reports_credentials_receiver.py`. Прежде чем запускать, обязательно сверить его контрольную сумму с зафиксированной в GitHub версией, затем `--check`. Полную установку проекта делать отдельно.
3. Проверить, что `/etc` принадлежит root и не позволяет запись группе/остальным. `/opt/mcp/secrets` принадлежит `hermes:hermes` (0700), поэтому использовать его для root-приёмника нельзя и **менять владельца существующего каталога нельзя**.
4. Для оператора подготовить действующий SSH-доступ **по ключу** и ограниченное право `sudo -n` на проверенный приёмник; право на произвольные команды sudo этому процессу не выдавать.
5. На Windows предварительно проверить ключ SSH и подлинность отпечатка сервера: `ssh -p PORT user@VPS`. Если соединение не подтверждено, ключи не вводить.

## Запуск с Windows (когда предыдущие шаги приняты)

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\Send-MspMarketplaceTokens.ps1" -SshTarget "root@KNOWN_HOST" -IdentityFile "$env:USERPROFILE\.ssh\msp_remote_ed25519" -Port 22
```

`KNOWN_HOST` — адрес подтверждённого VPS; вход как root на порт 22 с указанным ключом уже проверен. Точный порт и имя узла сверить по действующему одобренному доступу к VPS. **Не путать новый VPS VM-817589 со старым VM-684381.**

Скрипт сначала делает проверку готовности удалённого приёмника **без токенов**, затем запросит по очереди:
- WB Лазер-Мастер, Новокшенов, Дмитриева — по одному токену;
- Ozon Лазер-Мастер, Новокшенов, Дмитриева — Client-Id и API-Key.

После успешного ответа сервер вернёт только:
`RESULT=CREATED;CABINETS=6;SECRETS_PRINTED=NO;SERVICES_RESTARTED=NO`.

Если файл уже существует с другими значениями, по умолчанию операция будет отклонена. Осознанная ротация выполняется отдельным запуском с `-ReplaceExisting`, после неё создаётся закрытая резервная версия.

## После приёма

1. Проверить root-owned 0700/0600 и факт наличия **без вывода содержимого**.
2. Отдельно определить, какой сервисный пользователь будет читать ключи. При нынешнем root-only режиме непривилегированный агент не имеет к файлу доступа. **Не менять файл на 0644** — согласовать доступ через отдельный ограниченный сервис/группу или защищённую передачу.
3. Проверить принадлежность токенов кабинетам безопасными read-only API-проверками, с учётом общего ограничителя провайдера. Факт присутствия не доказывает действующий доступ.
4. Ни один отчёт не считать загруженным лишь по результату переноса ключей.

## Отказ / восстановление

Ошибки соединения, несогласованный host key, отсутствие утверждённого приёмника, отсутствие ограниченных прав sudo или неожиданный ответ приводят к отказу до передачи ключей либо к безопасному сообщению без секретов. Если связь оборвалась после отправки, **не повторять слепо**: сначала проверить факт установки и состояние файла без чтения токенов. Не выключать защиту проверки SSH ради обхода ошибки.

## Граница текущего этапа

Пока: только подготовка кода, проверок и инструкций в GitHub. На VPS **не запускали приём**, локальные ключи **не читали**, сервисы **не трогали**. Слияние и установка на VPS требуют отдельного согласования по регламенту проекта.

## Вариант для уже действующей root-консоли владельца (28.10.2026)

Поскольку WinSCP-доступ к каталогу секретов подтверждён, необязательно
собирать временный `cabinets.json` на компьютере. Подготовлен режим
`--interactive` в том же проверяемом `msp_reports_credentials_receiver.py`.

1. Сначала передать **только скрипт без секретов** через WinSCP в
   `/root/msp_reports_credentials_receiver.py` из конкретного GitHub-коммита.
   Рабочая копия GitHub в `main` и действующие службы не затрагиваются.
2. Проверить целостность файла из опубликованного коммита и состояние каталога;
   выполнить `python3 /root/msp_reports_credentials_receiver.py --check`.
3. Только при `RECEIVER_READY=YES;SECRETS_RECEIVED=NO` и наличии реального
   интерактивного SSH-терминала запускать `python3 /root/msp_reports_credentials_receiver.py --interactive`.
   Программа спросит девять секретов через `getpass` без отображения символов,
   затем один раз создаст `cabinets.json` с 0600. Нельзя вводить значения в
   текст Bash-команд, поскольку это может попасть в историю shell.
4. Если WinSCP показывает только интерфейс передачи команд без настоящего TTY,
   режим `--interactive` откажется до ввода. Использовать обычную интерактивную
   SSH-консоль (PuTTY/OpenSSH), а не менять исходный код для обхода проверки.
5. Если `cabinets.json` уже существует, повторный ввод не начнётся без
   явного `--replace`. Замена требует отдельной осознанной операции.

Файл программы не содержит реальных ключей, но это подготовительная
работа, **не включение нового архивного сервиса**. Не запускать `ingest.py`
без отдельной проверки реальной совместимости с ответами API и реестром покрытия.

## Уточнённый путь для действующего SSH-ключа (28.10.2026)
- Владелец подтвердил успешный вход под `root` на VM-817589 через Windows OpenSSH с существующим ключом `%USERPROFILE%\\.ssh\\msp_remote_ed25519`.
- Подготовительный приёмник в утверждаемой отдельной ветке следует сначала положить в `/root/msp_reports_credentials_receiver.py` (без секретов). Программа при этом **не запускается автоматически**. Ручная проверка: `python3 /root/msp_reports_credentials_receiver.py --check`.
- В Windows-отправителе обязательный `-IdentityFile`. Пример вызова **только после подтверждения размещения приёмника**: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\\Send-MspMarketplaceTokens.ps1 -SshTarget root@KNOWN_HOST -IdentityFile \"$env:USERPROFILE\\.ssh\\msp_remote_ed25519\" -Port 22`.
- Не менять права каталога с `0700`; файл ключей будет `0600`. Никакой `echo\"token\"` или записи открытого `cabinets.json` в папки WinSCP.

## Исправление после диагностики от 28.10.2026
- У владельца `/opt/mcp/secrets` оказался `hermes:hermes` с правами `0700` — это правильная отдельная зона Гермеса. Менять её владельца/права запрещено.
- Новый канонический путь реквизитов архива: `/etc/msp-marketplace-reports/cabinets.json`; каталог `root:root 0700`, файл `root:root 0600`. `/etc` защищён системным владельцем root. Старый пустой каталог под `/opt/mcp/secrets` **не является** местом хранения реквизитов.
- Приёмник, ранее перенесённый в `/root`, указывает на старый путь. Его сначала **заменить новой версией из GitHub с повторной проверкой контрольной суммы**. До этого отправку девяти реквизитов не начинать.
