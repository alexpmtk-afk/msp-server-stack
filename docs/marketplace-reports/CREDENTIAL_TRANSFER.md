# Перенос ключей шести кабинетов с Windows на VPS (проект МСП)

Статус 28.10.2026: код подготовки в PR №89. **До утверждения и установки выполнять нельзя.**

## Исходные условия

Владелец подтвердил: все действующие токены WB и Ozon находятся локально на его компьютере, **не на VPS**. Не нужно просить значения в чат, отправлять их через Gmail, Telegram, GitHub или загружать в Google Drive.

В `msp-server-stack` разработаны:
- `scripts/windows/Send-MspMarketplaceTokens.ps1` — локальная Windows PowerShell 5.1 программа с маскированным вводом;
- `scripts/remote/msp_reports_credentials_receiver.py` — серверный приёмник для запуска от root;
- `apps/msp_marketplace_reports/runtime.py` — последующее защищённое чтение реквизитов программой.

Итоговый путь на VPS (после развёртывания):
`/opt/mcp/secrets/msp-marketplace-reports/cabinets.json` (0600, root-owned).
Создаваемый каталог 0700, root-owned.

## Схема без временного открытого файла

```text
ПК владельца (Windows)
  -> Read-Host -AsSecureString (9 полей)
  -> JSON только в памяти процесса
  -> проверенный OpenSSH канал, stdin
  -> sudo -n python3 receiver.py
  -> root-owned 0600 JSON на VPS
```

Не использовать `ssh -o StrictHostKeyChecking=no`; первый отпечаток узла проверить по доверенному каналу. Не передавать секреты в аргументах команд, в журналах GitHub Actions, подставляя `echo`, или в файлах проекта.

## Подготовка один раз после принятого PR

1. Установить утверждённую версию проекта на VPS отдельной операцией по `docs/MSP_GITHUB_VPS_WORKFLOW.md`.
2. Проверить путь фактически установленного приёмника: `/opt/mcp/projects/msp-server-stack/scripts/remote/msp_reports_credentials_receiver.py`. Если путь отличается, сначала скорректировать утверждённый скрипт; не запускать случайные копии.
3. Проверить root-owned `/opt/mcp/secrets` и его отсутствие групповой/общей записи.
4. Для оператора подготовить действующий SSH-доступ **по ключу** и ограниченное право `sudo -n` на проверенный приёмник; право на произвольные команды sudo этому процессу не выдавать.
5. На Windows предварительно проверить ключ SSH и подлинность отпечатка сервера: `ssh -p PORT user@VPS`. Если соединение не подтверждено, ключи не вводить.

## Запуск с Windows (когда предыдущие шаги приняты)

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\windows\Send-MspMarketplaceTokens.ps1" -SshTarget "USER@KNOWN_HOST" -Port 22
```

`USER@KNOWN_HOST` и `22` — примеры, не проверенные значения. Точный порт и имя узла сверить по действующему одобренному доступу к VPS. **Не путать новый VPS VM-817589 со старым VM-684381.**

Скрипт сначала делает проверку готовности удалённого приёмника **без токенов**, затем запросит по очереди:
- WB Лазер-Мастер, Новокшенов, Дмитриева — по одному токену;
- Ozon Лазер-Мастер, Новокшенов, Дмитриева — Client-Id и API-Key.

После успешного ответа сервер вернёт только:
`RESULT=CREATED;CABINETS=6;SECRETS_PRINTED=NO;SERVICES_RESTARTED=NO`.

Если файл уже существует с другими значениями, по умолчанию операция будет отклонена. Осознанная ротация выполняется отдельным запуском с `-ReplaceExisting`, после неё создаётся закрытая резервная версия.

## После приёма

1. Проверить root-owned 0700/0600 и факт наличия **без вывода содержимого**.
2. Отдельно определить, какой сервисный пользователь будет читать ключи. При нынешнем root-only режиме непривилегированный агент не имеет к файлу доступа. **Не менять файл на 0644** — согласовать доступ через отдельный ограниченный сервис/группу или защищённую передачу.
3. Проверить принадлежность токенов кабинетам безопасными read-only API-проверками, с учётом общего ограничителя провайдера. Факт присутствия не доказывает действующий доступ.
4. Ни один отчёт не считать загруженным лишь по результату переноса ключей.

## Отказ / восстановление

Ошибки соединения, несогласованный host key, отсутствие утверждённого приёмника, отсутствие ограниченных прав sudo или неожиданный ответ приводят к отказу до передачи ключей либо к безопасному сообщению без секретов. Если связь оборвалась после отправки, **не повторять слепо**: сначала проверить факт установки и состояние файла без чтения токенов. Не выключать защиту проверки SSH ради обхода ошибки.
