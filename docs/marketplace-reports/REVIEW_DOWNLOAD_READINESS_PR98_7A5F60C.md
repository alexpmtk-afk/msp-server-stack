## 5. PR98: конкретный дефект R98-1 и остальная проверка

**R98-1 — несогласованная инвентаризация legacy FINAL**, backfill_plan.py:33–36.

Ветка Ozon проверяет annual и его meta через exists(), не is_symlink(), а любой существующий monthly_source directory принимает за legacy evidence. Это не та же политика, что versioned_archive._assert_no_legacy.

Воспроизводимые искусственные варианты:

1. Опубликовать исправное Ozon FINAL поколение. Создать в старом layout dangling symlink вместо annual CSV; monthly_source отсутствует. Планировщик возвращает LOCAL_VERIFIED, реальный importer отказывает. То же для annual meta.
2. При исправном новом поколении создать только пустой старый monthly_source directory. Планировщик возвращает MIXED_UNSAFE, importer разрешает, поскольку старых финансовых файлов/manifest нет.

В результате план может отправить VERIFY_PROVIDER_COVERAGE вместо REVIEW_ARCHIVE либо без причины заблокировать готовую область. Это **ошибка диагностики/планирования**, не доказательство обхода write-защиты: импортёр остаётся fail-closed.

**Минимальное исправление за автором:** общий read-only inventory helper, согласованный со штатным importer guard: проверять CSV/meta и dangling symlinks, полный год для FINAL, не считать пустой контейнер финансовыми данными. Никакой новой подсистемы восстановления не требуется. Добавить эти 3 регрессии. До исправления PR98 не принимаю целиком; это не основание останавливать параллельную работу над квотами/загрузчиком.

Положительное: 14 календарных случаев, оба WB типа в обоих layout, пропуски ID и отсутствие записей планировщика; missing CURRENT с generation evidence корректно даёт REVIEW_ARCHIVE/VERIFY_FAILED, не download. На 30 октября у пустого synthetic root ожидаются именно 39 задач, не количество реальных серверных пропусков.
