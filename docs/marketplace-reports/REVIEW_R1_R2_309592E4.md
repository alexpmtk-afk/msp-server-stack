## B7 — три воспроизведённых аварийных точки

После исправного января искусственно вызван OSError:

- запись нового monthly CSV завершена, его manifest не записан;
- новая месячная пара уже записана, публикация annual ещё не началась;
- новый annual CSV записан, его manifest не записан.

Во всех трёх случаях verify=False, обычный повтор отклонён, при повторе файлы уже прерванного состояния не меняются. Это корректный fail-closed: повреждённое/несогласованное состояние не получает новую контрольную сумму. **Но автоматического rollback/recovery нет**, а первая прерванная операция уже могла изменить часть файлов. Не удалять защиту, не пересчитывать checksum и не обещать транзакционность.

Известный B8 также не закрыт: например, verify по-прежнему не заменяет независимый ожидаемый inventory пропавших документов. Новый group-preflight улучшает отказ при нарушенном month/year наборе, но не является доказательством исторической полноты.

## R3 — унаследованная нестрогая типизация метаданных

`apps/msp_marketplace_reports/archive.py:138–142`, `_verify_previous` использует обычное сравнение Python. В Python `True == 1`.

Искусственное воспроизведение на месяце с одной строкой:

1. Создать исправный январь штатным импортом.
2. Заменить только manifest.schema `1` на JSON `true` (отдельно повторить с manifest.rows `1` → `true`).
3. Импорт февраля принимается, verify=True.

Подтверждено **и на e98000b, и на 309592e4**. Третий диагностический вариант показывает, что численно равный float в bytes также принимается; допустимость `N.0` должна определяться явным контрактом, а не предположением ревизора. Однозначное замечание — boolean выдаётся за schema/version или row count. Денежные строки в этом контрпримере не менялись.

Предложение отдельной доработки: определить JSON-типы обязательных полей и валидировать их перед сравнением; исключить bool для integer schema/rows/bytes, проверить допустимые значения и диапазоны; добавить positive/negative tests. Это ограниченный остаток строгого manifest-контракта, не повтор первоначальной B5 с повреждённым amount и не новая регрессия R1/R2.
