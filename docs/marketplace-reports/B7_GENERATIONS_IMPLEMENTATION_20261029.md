# B7 — первый опытный программный блок поколений, НЕ производственный переход

Дата: 29.10.2026. Автор: ChatGPT. Проверка коллегой Hermes ожидается.
Источник требований: ветка PR №90, \`B7_FAULT_TEST_PLAN_20261029.md\`, 24 категории F01–F24.

## Реально реализовано в PR №95

- Добавлен отдельный, пока **не подключённый к текущему импорту** модуль
  \`apps/msp_marketplace_reports/generation_store.py\`.
- \`publish_batch(root, dataset, cabinet, period, files, expected_generation=...)\`
  принимает целиком подготовленный набор байтов: обычный WB/Ozon CURRENT —
  один CSV+manifest; Ozon FINAL — все месяцы затронутого года плюс annual.
- Перед первой записью проверяются имена и область файлов, пары CSV/manifest,
  строгий JSON с запретом повторов ключей, типы schema/rows/bytes, SHA,
  dataset/cabinet/period, ключи строк, соответствие WB type и годового Ozon его
  месяцам. Никакой новый checksum повреждённого источника не считается допустимым.
- В каталоге \`.b7-generations/<dataset>/<cabinet>/<period>/generations/<id>/\`
  создаётся новый **неизменяемый** набор файлов и \`generation.json\`;
  проверяется его содержимое до переключения указателя.
- Файл \`CURRENT.json\` заменяется атомарно через \`_safe_write\` после
  сохранения и проверки полного поколения. Это точка публикации для
  **нового, явно opt-in** интерфейса. \`read_active()\` читает CURRENT однократно
  и далее только иммутабельное поколение; \`read_generation()\` читает
  закреплённое старое поколение.
- Переключение защищено областью \`flock\` и \`expected_generation\`.
  При исчезнувшем ответе **после** commit результат помечается
  \`CommitUncertainError\`, а не объявляется невыполненной записью.
- \`reconcile()\` читает текущее состояние под тем же писательским lock,
  указывает \`ACTIVE_VERIFIED / PENDING / RECOVERY_REQUIRED / EMPTY\`,
  сохраняет orphan и проверенные поколения **без удаления и без записи
  старых архивных путей**. Этот метод **не является automatic recovery**.
- Код B7 не вызывает сеть, Redis, API WB/Ozon, секреты, не меняет VPS.

## Точные ограничения — НЕ считать B7 закрытым

1. \`archive.import_csv()\`, \`archive.verify()\`, \`cli.py\`, \`ingest.py\`
   и внешние читатели старых CSV **пока не используют поколение**.
   Согласованный снимок гарантируется только для нового интерфейса
   \`read_active/read_generation\`; старый layout остаётся старым.
2. \`reconcile\` не выполняет восстановление предыдущего проверенного поколения
   при повреждении CURRENT или активного поколения, не очищает orphan и не
   восстанавливает legacy. Не реализованы журнал завершения recovery и
   отдельная разрешённая CLI-команда восстановления.
3. Не проверена целиком матрица F01–F24. Реализованы отдельные синтетические
   прерывания до/после commit, отказ до записи первой пары, контроль целостности,
   неверные пути/ссылки, параллельные писатели, согласованность FINAL и
   закреплённый читатель. Остаются более тяжёлые ENOSPC/fsync, SIGKILL,
   повреждения истории, миграция и power-loss. Не считать monkeypatch
   эквивалентом отключения питания.
4. Размеры батчей пока не ограничены; материализация полного года в памяти
   требует последующей потоковой реализации. Верификация происхождения API
   и обязательного инвентаря источников B8 также **не реализована**.
5. В прежней \`archive._safe_write\` остаётся отдельная оценка короткой записи,
   durability файловой системы и отказа после rename. Нет внешнего разрешения
   вводить новый формат на VPS или запускать API-загрузку.
6. B9 в отдельном PR №92. Новый generation core имеет собственную строгую
   проверку \`reportType\`, но не означает слияния или внедрения PR №92.

## Дополнительная защита и измеренный результат

- Добавлена проверка символьных ссылок **до** `mkdir` каталога поколения: подмена промежуточного пути не должна приводить к созданию каталогов за пределами archive root.
- Родительская цепочка подтверждённых поколений проверяется отдельно; старые committed поколения **не считаются** аварийными orphan. Неопубликованные поколения после сбоя распознаются отдельно, вызывают `RECOVERY_REQUIRED` (при наличии старого активного поколения) или `PENDING` (на первом импорте) и блокируют следующую запись до отдельного решения о восстановлении. Автоматического удаления нет.
- Два одновременных писателя одной области проверены с искусственной задержкой под `flock`; второй со старым `expected_generation` отклоняется, читатель остаётся на полностью подтверждённом поколении.
- На кодовом SHA `bc7c9bb040894c3443d69ea223e5df9afdf37a40` GitHub Actions `MSP Marketplace Reports Offline Tests` — **81 тест OK**, `windows-ps51-parse` PASS, `Secret scan` PASS. Из них **17 новых** тестов `test_msp_marketplace_generations.py`, остальные 64 теста R3/архива. Дальнейшие документационные коммиты требуют повторной проверки итогового SHA.
