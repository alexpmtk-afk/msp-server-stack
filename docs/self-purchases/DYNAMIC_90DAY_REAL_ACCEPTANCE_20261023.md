# МСП Самовыкупы — исправление 90-дневного окна и реальная приёмка (23.10.2026)

## Причина исправления
Обнаружено несоответствие владельческой логике: стандартное сравнение ошибочно ограничивалось 30 календарными днями после записанной даты отзыва, хотя спустя более 90 дней должна была строиться **полная симметричная история за 90 дней**.

## Действующая формула
Для каждой отдельной даты `review_date` внутри одного ключа `(marketplace, store, marketplace_sku)`:

`N = min(90, (as_of - review_date).days - 1, ((next_review_date - review_date).days - 1) if next_review_date else 90)`, обрезая отрицательные значения до нуля.

- `as_of` — дата текущего незавершённого дня (не включать в наблюдение).
- Дата самого отзыва исключается.
- ДО: `[first_review_date - N, first_review_date - 1]`; ПОСЛЕ: `[checkpoint_review_date + 1, checkpoint_review_date + N]`.
- Несколько дат отзывов: отдельная контрольная точка на каждую уникальную дату; для более ранней контрольной точки период после неё заканчивается строго перед следующей датой отзыва; без доказательств каузальная оценка запрещена.
- При `N<90` результат `SHORTER_EQUAL_WINDOW_PRELIMINARY`; при `N=90` — `FULL_EQUAL_WINDOW`; когда `N=0` — `POST_WINDOW_PENDING`.
- Старые 30-дневные сравнения остаются архивными/явно запрошенными промежуточными, но не подставляются в итог за 90 дней.
- `quantity` — повторённый по строкам план карточки, не аддитивное число выкупов. `sales/revenue` MPSTATS — внешние оценочные заказы и их сумма, не подтверждённые оплаченные органические продажи; возвраты и причинный эффект не выводить из них.

## Реальная серверная приёмка
[Private bridge #585](https://github.com/alexpmtk-afk/msp-server-bridge/issues/585): `INSTALLED_90DAY_LIVE_PASS`, рабочий исторический WB SKU определён по существующему каталогу `product_listing`, прошёл проверку исходного реестра и обоих ровно 90-дневных датированных MPSTATS `wb_sku(full)` окон. Проверены интервалы `2026-03-19..2026-06-16` и `2026-06-18..2026-09-15` при `review_date=2026-06-17` и `as_of=2026-10-23`. Все 2/2 окна вернули данные; русский отчёт сформирован. Бизнес-показатели конкретной карточки сохранены **только в закрытом приватном issue**, не переносятся в публичную документацию. Установлено 9 изменённых файлов с SHA readback, 67 остальных оставлены без изменений; исходные архивы, база SQLite, товары и Gateway не менялись; создан rollback backup.

**Приёмка Telegram-вызова именно в момент ответа пользователя отдельно не доказана**; успешный read-only серверный результат не должен изображаться как независимый Telegram execution trace. Не запускать покупки/отзывы или иные операции изменения маркетплейса.
