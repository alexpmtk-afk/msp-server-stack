# МСП Самовыкупы — самостоятельная сверка источников MPSTATS для истории оценок (27.10.2026)

## Вывод

**Данные в интерфейсе есть; полнота доступа к тем же полям через действующий MCP пока не доказана.** Нельзя просить владельца вручную искать заведомо документированные показатели или утверждать, что их нет в MPSTATS. Можно исследовать действующий read-only набор инструментов без изменения кабинета/заказов/отзывов, но нельзя считать найденное имя метода успешной загрузкой ряда.

### Официальные первоисточники

1. [MPSTATS, Поиск по SKU (WB), «Отзывы и рейтинг»](https://wiki.mpstats.io/Wildberries/%D0%9F%D0%BE%D0%B8%D1%81%D0%BA_%D0%BF%D0%BE_SKU): для карточки WB заявлены четыре датированных ряда **«Оценок»**, **«Негативных оценок»**, **«Оценок с отзывами»**, **«Негативных оценок с отзывами»**. Негативными названы 1, 2, 3★. После доказательства того, что все четыре счётчика относятся к одной карточке, дате и одному типу ряда, 4–5★ = все − негативные; 4–5★ с текстом = с текстом − негативные с текстом. Не спутать дневные события с накопительными снимками.
2. [MPSTATS, Карточка товара в Кабинете WB](https://wiki.mpstats.io/ru/%D0%9B%D0%B8%D1%87%D0%BD%D1%8B%D0%B9_%D0%BA%D0%B0%D0%B1%D0%B8%D0%BD%D0%B5%D1%82/%D0%9A%D0%B0%D1%80%D1%82%D0%BE%D1%87%D0%BA%D0%B0_%D1%82%D0%BE%D0%B2%D0%B0%D1%80%D0%B0): «Новые отзывы за день» и «Средняя оценка за день». **Не** позволяют без разбивки по звёздам вычислять новые 4–5★.
3. [MPSTATS, Анализ отзывов](https://wiki.mpstats.io/Wildberries/%D0%90%D0%BD%D0%B0%D0%BB%D0%B8%D0%B7_%D0%BE%D1%82%D0%B7%D1%8B%D0%B2%D0%BE%D0%B2): требует **не менее 20 отзывов**, группирует оценки; не является гарантированным источником полной истории редкой новой карточки.
4. [Официальный MCP MPSTATS](https://mpstats.io/instruments/ai/mcp): MCP работает лишь с частью инструментов платформы. Наличие функции в пользовательском интерфейсе не означает такого же ответа через MCP.
5. [MPSTATS, «Отзывы» раздела Автоответы](https://wiki.mpstats.io/ru/%D0%A1%D1%82%D1%83%D0%B4%D0%B8%D1%8F/%D0%90%D0%B2%D1%82%D0%BE%D0%BE%D1%82%D0%B2%D0%B5%D1%82%D1%8B/%D0%9D%D0%BE%D0%B2%D1%8B%D0%B5_%D0%BE%D1%82%D0%B7%D1%8B%D0%B2%D1%8B): внутри авторизованного продавцом подключения имеются SKU, дата, оценка, текст и ID отзыва; раздел «Новые отзывы» ограничен 30 днями, далее архив. Доступность этой истории через действующий MCP **не проверена**; не инициировать отправку ответов.

### Реальный MCP на сервере (инвентаризация 26.10, приватный [#624](https://github.com/alexpmtk-afk/msp-server-bridge/issues/624))

- `tools/list`: 108 зарегистрированных инструментов, включая `wb_sku` с `report=comments`, `report=by_period`; `lk_wb_card_table(type=articles,value=SKU,period_type=90days)`, `lk_wb_card_info`, `lk_wb_card_widget`, а также универсальный `lk_wb_request`.
- `wb_sku(comments)`: без зависимости от `d1/d2`; в сохранённом реальном ответе — одна датированная запись с текстом 5★ на SKU `1415941897`. Не доказаны историческая полнота, наличие ID/пагинации для всех отзывов и независимость автора. Загрузка одного отзыва не равна всему числу новых отзывов.
- `wb_sku(by_period)`: реальная сохранённая дневная структура содержит `rating` и `comments`, но не четыре рейтинговых счётчика. `rating=0` не означает нулевую звёздность; разность `comments` — изменение наблюдаемого счётчика, не доказанное число новых публикаций.
- `lk_wb_card_table`: после выбора кабинета в сохранённой пробе получен HTTP **403**. Это ограничение реального доступа, а не отсутствие функциональности на сайте. Не пытаться обходить права доступа или подменять недостающие данные.
- Универсальный `lk_wb_request`: зарегистрирован, но точный доступный read-only путь, контракт полей и права **не проверены**. Не считать готовым источником четырёх рядов.
- Неподтверждённый `dated_rating_dynamics.py` уже принимает строго проверенные четыре счётчика за датированный период и различает ежедневные новые значения от чистой разницы накопительных снимков. `dated_review_activity.py` отдельно поддерживает число новых отзывов и среднюю оценку, но не вычисляет положительные звёзды без разбиения.

## Следующая самостоятельная исследовательская задача

1. Из открытой документации/реально сохранённых контрактов определить, как именно интерфейс «Поиск по SKU» получает четыре серии: есть ли документированный **read-only** путь API/MCP для каждой и какие права нужны. Не обращаться к недокументированным обходам 403.
2. Для авторизованного пути проверить реальные имена полей, карточку и кабинет, даты, полную выгрузку и тип рядов (дневные/накопительные), дубли и пропуски. Подтверждать фактический результат только после ответа MCP, а не по описанию сайта.
3. При валидном источнике подключить нормализующий адаптер к существующему `dated_rating_dynamics.py`, добавить тесты частичной истории. Иначе оставить `UNKNOWN` и сохранить конкретный доказанный отказ/недоступность.
4. Различать стадии `UI_DOCUMENTED`, `MCP_TOOL_REGISTERED`, `MCP_ACCESS_CONFIRMED`, `DATED_FIELD_CONTRACT_VERIFIED`, `LIVE_REPORT_ACCEPTED`. Пока подтверждены первые две, третья для `lk_wb_card_table` отрицательная (403).

**Без действий в кабинете/маркетплейсах, без искусственных заказов/отзывов, без раскрытия токенов. Денежная окупаемость отложена.**
