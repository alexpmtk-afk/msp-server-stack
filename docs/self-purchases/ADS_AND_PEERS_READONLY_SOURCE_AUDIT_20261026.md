# Реклама и конкуренты — проверка MPSTATS для ретроспективного анализа МСП

Дата: 26.10.2026. Все запросы к MPSTATS — **только чтение**. Никаких изменений рекламных кампаний, ставок, товаров, SQLite, Telegram и Gateway.

## Реально проверенные источники

- [Приватная приёмка #646](https://github.com/alexpmtk-afk/msp-server-bridge/issues/646): `wbbidder_cabinets` вернул **один подключённый рекламный кабинет**. Однако независимая связь этого кабинета с магазином `novok` в исходном исследуемом SKU ещё не подтверждена.
- `wbbidder_products(report=list,nm_id=<SKU>,d1,d2)` на двух равных исторических окнах и `wbbidder_campaigns` вернули структуру без строк данного SKU; это **не подтверждает отсутствие рекламы или нулевые рекламные расходы**. Пустые строки нельзя превращать в ноль бюджета.
- `wb_similar(report=products,family=similar)` вернул минимум 20 предварительных карточек с полями `subject`, `final_price`, `sales`, `days_in_stock`, `rating` и другими. **Ни один не принят как сопоставимый конкурент** без независимой проверки характеристик, комплектации, назначения и ценового сегмента. Совпадение предмета — только предфильтр.
- [Приватная приёмка #647](https://github.com/alexpmtk-afk/msp-server-bridge/issues/647): подтверждён документированный read-only `wbbidder_products(report=sku,nm_id=<SKU>)`, который *по контракту* содержит `data` по дням, `laststocks`, `pricefinal` и рекламные данные. Однако **на исследуемом SKU фактический режим `sku` вернул `TOOL_ERROR`** (уточнение [#648](https://github.com/alexpmtk-afk/msp-server-bridge/issues/648)); реального датированного ряда не получено. `pricefinal` не принимать за историческую цену конкретного покупателя без подтверждения вида цены, периода и кабинета.
- `lk_wb_pulse_products` (собственная воронка товара, `advert_amount`, `drr`, `funnel`, `orders`, `rating`) для тех же двух интервалов также вернул `TOOL_ERROR`, не источник подтверждённых данных по SKU.

## Обязательные правила качества

Историческое рекламное наблюдение принимается только когда:
1. подтверждены конкретный SKU и магазин/кабинет; строка данных действительно относится к ним;
2. подтверждены обе даты исследуемого окна и одинаковая гранулярность ДО/ПОСЛЕ, без сегодняшних незавершённых точек;
3. зафиксированы фактические единицы затрат, показов, кликов, заказов, дат и валюты; пустой ответ ≠ ноль расходов;
4. доступно независимое сравнение с журналом `v_price_history` и днями наличия; запрещена причинная атрибуция только по совпадению.

Сопоставимые конкуренты принимаются только после проверки назначения, основных характеристик, объёма/комплектации и ценового сегмента. Предварительный список `wb_similar` **не является контрольной группой**, статистической оценкой эффекта отзыва и доказательством окупаемости.

**Текущие состояния:** `ADVERTISEMENT_EFFECT_UNKNOWN`, `NO_VERIFIED_COMPARATORS`, `MPSTATS_DATED_BUYER_PRICE_HISTORY_NOT_VERIFIED`. Незавершённые источники не должны блокировать **отдельно подтверждённый** описательный отчёт MPSTATS по заказам и наличию, но обязаны ограничивать бизнес-вывод.

**Приоритет изменён владельцем 26.10.2026:** НЕ планировать привязку рекламного кабинета для данного исследования. Вместо этого использовать уже доступную **внешнюю аналитику** MCP `wb_sku(report=search_stats/keywords)` и `wb_shelves(report=stats/items)`, отдельную от рекламного кабинета. Реальные результаты, границы и ограничения — [EXTERNAL_AD_VISIBILITY_MPSTATS_RESEARCH_20261026.md](./EXTERNAL_AD_VISIBILITY_MPSTATS_RESEARCH_20261026.md). Подтверждать даты и типы рекламной видимости, не преобразовывать их в расходы, платные заказы или ROI. Для исследования не использовать методы `wbbidder_*`, `lk_*` и изменяющий аккаунт `wb_shelves_project`.

## Установка обязательных предупреждений в рабочий Hermes

В [приватной приёмке №650](https://github.com/alexpmtk-afk/msp-server-bridge/issues/650) подтверждено `INSTALLED_AD_PEER_EVIDENCE_PASS`: 4 файла рабочей среды обновлены с резервной копией, два исторических окна MPSTATS реально доступны, а русский отчёт Hermes **прямо говорит** «реклама не подтверждена, отсутствие строк не означает 0 ₽» и «подтверждённых сопоставимых конкурентов нет». Сохранился уже установленный числовой расчёт оценочных заказов на день наличия. Никаких действий над маркетплейсами, SQLite, Telegram и Gateway.

В коде это статусы `advertising_evidence_status=UNVERIFIED_FOR_SKU_AND_WINDOW` и `verified_comparator_status=NO_VERIFIED_COMPARATORS`. Для синтетической приёмки добавлена проверка обязательных русских предупреждений. Статусы отражают отсутствие **проверенного источника на нужные даты**, но не доказывают отсутствие рекламных кампаний и не утверждают, что на товар не влияли конкуренты.


## Продолжение 26.10.2026: попытка датированного сравнения предварительных WB-кандидатов

Для исторического WB SKU из существующей SQLite рассчитаны одинаковые **34 полностью завершённых дня**: ДО 18.08–20.09.2026 и ПОСЛЕ 22.09–25.10.2026. День записанного отзыва 21.09 исключён. Для проверки создан только read-only серверный сценарий с максимум двумя кандидатами из семейства MPSTATS wb_similar(family=identical); название этого режима не подтверждает идентичность товара.

- [Приёмка №669](https://github.com/alexpmtk-afk/msp-server-bridge/issues/669): PARTIAL, этап OWN_CARD, причина OWN_CARD_UNAVAILABLE — для **этого** SKU пригодная структура wb_card_content не получена. Это **не отменяет** успешное получение wb_card_content со строковым SKU для других карточек в прежних приёмках №561–566. Доступность зависит от запроса и товара.
- [Повтор №670](https://github.com/alexpmtk-afk/msp-server-bridge/issues/670): добавлен безопасный вариант без подмены отсутствующих характеристик (проводить только описательную историю кандидатов). Однако фактический запуск остановился раньше, на MCP_INIT_FAILED; расчёт кандидатов, датированных оценочных заказов и наличия **не состоялся**.

**Итог текущего этапа:** проверка исторической конкурентной динамики по выбранному SKU **НЕ пройдена**. Нет новых подтверждённых сопоставимых конкурентов, нет новой контрольной группы, нет причинной оценки влияния отзывов. Исследование не требует новых рекламных кабинетов, 1С и изменения маркетплейсов. Не запускать неконтролируемые повторные пробы при недоступном MCP; для следующего безопасного запуска сначала восстановить стабильное read-only соединение и доступность wb_sku(full) по кандидатам за оба окна.

Сценарий исследования находится в приватном msp-server-bridge/scripts/remote/msp_self_peer_equal_windows_20261026.py; **он не установлен в Hermes как рабочая аналитика** и не подменяет действующий отчёт.
