# МСП Самовыкупы — нестоимостной анализ и история положительных оценок (26.10.2026)

## Готово и подтверждено

- На рабочем Hermes существует read-only аналитика по зарегистрированным датам отзывов, равным завершённым окнам, оценочным заказам MPSTATS и дням наличия, с отдельными замечаниями о ценах и непроверенной причинности.
- На VPS 26.10 установлена защита неполной истории MPSTATS `client_price`: [приёмка #668](https://github.com/alexpmtk-afk/msp-server-bridge/issues/668).
- Для одной WB-карточки выполнены равные 34-дневные сравнения MPSTATS и двух **предварительных** кандидатов: [приёмка #672](https://github.com/alexpmtk-afk/msp-server-bridge/issues/672). Похожесть карточек не доказана. Результат не является оценкой эффекта зарегистрированного отзыва.
- В публичной feature-ветке добавлены чистые модули `nonfinancial_outcome.py`, `peer_history_context.py`, `dated_rating_dynamics.py` и unit-тесты. **Новые модули НЕ установлены в рабочий Hermes, и новый полный текстовый отчёт в Telegram не принят.** Код и установка — разные стадии.

## Какие отзывы и рейтинги действительно доступны в MPSTATS

По официальной справке MPSTATS, страница [«Поиск по SKU (WB)»](https://wiki.mpstats.io/Wildberries/%D0%9F%D0%BE%D0%B8%D1%81%D0%BA_%D0%BF%D0%BE_SKU), «Отзывы и рейтинг», показывает датированную динамику: «Оценок», «Негативных оценок», «Оценок с отзывами», «Негативных оценок с отзывами». Негативные оценки — **1, 2 и 3 звезды**. Положительные по этой классификации — **4 и 5 звёзд**. Отдельно сервис показывает рейтинг карточки, который не заменяет количество датированных отзывов.

Справка MPSTATS [«Карточка товара в Кабинете WB»](https://wiki.mpstats.io/ru/%D0%9B%D0%B8%D1%87%D0%BD%D1%8B%D0%B9_%D0%BA%D0%B0%D0%B1%D0%B8%D0%BD%D0%B5%D1%82/%D0%9A%D0%B0%D1%80%D1%82%D0%BE%D1%87%D0%BA%D0%B0_%D1%82%D0%BE%D0%B2%D0%B0%D1%80%D0%B0) содержит в дневной таблице «Новые отзывы за день», «Новые отзывы за день с фото», «Средняя оценка за день» и общий «Рейтинг WB». **Средняя оценка за день и общее число отзывов недостаточны, чтобы точно восстановить число 4–5-звёздочных отзывов** без распределения оценок.

Реальная серверная инвентаризация MCP [#624](https://github.com/alexpmtk-afk/msp-server-bridge/issues/624) подтверждает методы:
- `wb_sku(report=comments)`, но документация инструмента говорит, что report=comments **не зависит от d1/d2**;
- `wb_sku(report=by_period)`; в серверной пробе [#514](https://github.com/alexpmtk-afk/msp-server-bridge/issues/514) получен `NO_JSON_PAYLOAD`, не принята историческая серия;
- `lk_wb_card_table(type=articles,value=...,period_type=90days)`, у которого по схеме есть `period_type`, `type`, `value`, `self_redemption`, но нет прямых `d1/d2`. **Метод найден, однако дата/состав/семантика полей ответа на реальном SKU до сих пор не проверены.**
- Ранее `wb_sku(comments)` [#533](https://github.com/alexpmtk-afk/msp-server-bridge/issues/533) успешно вернул структуру, но **нулевое число распознанных датированных отзывов**. Это не доказывает, что отзывов нет.

Прямого установленного MPSTATS-плагина в данном чате нет. Попытка активировать новый серверный read-only аудит через GitHub была заблокирована; без его успешного readback нельзя заявить о проверке `lk_wb_card_table`.

## Строгий расчёт — только после подтверждения контракта MCP

Разработан `apps/msp_self_analytics/dated_rating_dynamics.py`, который **не вызывает сеть** и принимает исключительно подготовленный адаптером набор четырёх числовых счётчиков по датам: `ratings_total`, `ratings_negative`, `ratings_with_text`, `ratings_negative_with_text`. Эти имена — **внутренний контракт**, а не установленная схема ответа MPSTATS MCP.

Расчёт:

- положительные оценки (4–5★) = все оценки − негативные (1–3★);
- положительные оценки **с текстовым отзывом** = все оценки с текстом − негативные оценки с текстом;
- когда источник содержит строго **дневные новые оценки**, все даты интервала после контрольной даты обязаны присутствовать; пропуск хотя бы одного дня → `UNKNOWN`, не 0;
- когда источник содержит **накопительные счётчики**, разность между концом окна и предыдущим днём — лишь чистое изменение, **не точное количество новых публикаций**, поскольку могли быть удаления/модерация;
- контрольный день отзыва исключён; дата в реестре не равна проверенной дате публичного появления, а личность/независимость автора по агрегатам не определяется;
- отсутствие `source_ref`, типа серии, дневной гранулярности, некорректные числа, нарушение вложенных сумм, дубликаты дат, неполный ряд → `UNKNOWN`;
- расчёт не устанавливает эффект самовыкупа или денежную окупаемость.

Модуль подключён к `nonfinancial_outcome.py` и `self_purchase_analysis.py` **опционально** через `dated_rating_sources`. Пока реальный проверенный адаптер не реализован, этот аргумент не подаётся, и рабочий результат остаётся «история новых положительных оценок НЕИЗВЕСТНА».

## Незакрытая приёмка

1. Read-only подтвердить реальный `lk_wb_card_table` и/или другой исторический счётчик на нескольких собственных SKU, без передачи секретов/текста отзывов/персональных данных в открытый GitHub.
2. Проверить дневной или накопительный характер ряда, полноту точных окон, 4-звёздочные и 5-звёздочные оценки отдельно от 1–3 и текстовых отзывов; если схема MCP не позволяет, сохранить статус UNKNOWN.
3. Только после этого добавить проверенный адаптер, развернуть новый расчётный модуль с резервной копией и readback, проверить реальный русский ответ Hermes/Telegram.
4. Денежную окупаемость не требовать: отложена владельцем до получения финансовых данных.


## Продолжение: частичный дневной ряд `lk_wb_card_table`

Официальная документация «Карточка товара в Кабинете WB» подтверждает **два отдельных** показателя: «Новые отзывы за день» и «Средняя оценка за день». В публичной аналитике «Поиск по SKU» отдельно доступны четыре ряда, которые потенциально позволяют вычислить положительные 4–5★.

В feature-ветке реализован `apps/msp_self_analytics/dated_review_activity.py` — чистый расчёт, принимающий **только подтверждённый** дневной ряд `new_reviews` и `average_rating`, который заранее сопоставил и проверил адаптер MPSTATS. При полном наборе календарных дат за окно ПОСЛЕ модуль возвращает количество отзывов и взвешенную по количеству отзывов среднюю оценку. **Ни одно из этих значений не даёт точного числа положительных отзывов 4–5★**, если отсутствует распределение по звёздам. При пропуске дня, неполном или неоднозначном типе источника — `UNKNOWN`, а не ноль. Внутренние имена полей — контракт расчёта, **не подтверждённая схема MCP**.

Модуль опционально подключён в `nonfinancial_outcome.py` → `self_purchase_analysis.py` через аргумент `dated_review_activity_sources`. При наличии независимого проверенного ряда он может дать честный частичный итог «после контрольной даты появилось N отзывов, средняя оценка M», одновременно сохранив **«точное число положительных неизвестно»**. Исходные отзывы, имена покупателей, атрибуция и публикация не восстанавливаются по агрегатам. Код покрыт синтетическими unit-тестами и не делает сетевых запросов.

**Статус внедрения не изменился:** реальный ответ `lk_wb_card_table` по выбранному SKU в MCP не получен, адаптер к фактическим полям не принят, Hermes на VPS этой новой функцией не обновлялся. Не объявлять задачу отзывов завершённой до настоящей приёмки.
