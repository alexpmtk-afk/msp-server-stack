# История оценок WB и Ozon: контракт источников

## Уточнение владельца 28.10.2026

Приоритет — дата и звёздность каждой оценки, а не текст отзыва.
Контрольная дата T берётся из `review_date` («Дата отзыва»), никогда из
`purchase_date`. По указанию владельца зарегистрированное собственное событие
относится к собственной оценке 5★. Это декларация владельца, а не найденный
по одному совпадению даты идентификатор публичного отзыва.

Нужны два самостоятельных результата:

1. Рейтинг карточки на T−1 и последнее доступное датированное наблюдение.
2. Полученные отдельные оценки до/после T: число 1, 2, 3, 4, 5★, средняя
   этих оценок, список дат и звёзд без текста, отдельный учёт своих оценок.

Дата запроса и дата последнего наблюдения показываются отдельно. MPSTATS
by_period обслуживает завершённые сутки; это не гарантированный рейтинг
прямо сейчас. Средняя оценок периода не равна среднему дневных рейтингов.
Рейтинг карточки остаётся фактом источника, он может включать собственную
оценку: нельзя вычесть 5 из взвешенного/округлённого рейтинга и получить
«рейтинг без нас». Готовые формулы dated_rating_dynamics не меняются.

При наличии подтверждённого ID собственная запись исключается точно. Если
есть только день, все записи дня собственного отзыва откладываются отдельно:
нельзя произвольно назвать одну из нескольких пятёрок своей. Это может
исключить из сравнения и чужие оценки того же дня; ограничение обязательно
показывается. Учитывать все зарегистрированные собственные даты в периоде.
Непомеченные записи не объявлять доказанно независимыми покупателями.

## Доступ и фактическая проверка

Работают отдельные `wb_sku` и `ozon_sku`: `by_period` даёт дневные
наблюдения, `comments` — датированную выборку оценок, в том числе без текста.
Проверены современные периоды и ряды 2024 года на реальных товарах.
Проверочные товары, исходные ответы и коммерческие результаты хранятся
локально, не в публичном репозитории.

WB comments — объект с comments и last_request; Ozon — список, без
подтверждённого времени обновления. Запрос Ozon comments с d1/d2 фактически
возвращал записи вне периода: необходим локальный отбор дат. Нет контракта
полноты, total, стабильных ID и доступной пагинации этих двух выборок.
Завершённый дневной ряд не доказывает полноту отдельных оценок.

Ozon `no_data=1` и WB `daynum=0` — не наблюдения, не нулевые значения.
`rating=0` не считается оценкой 0★. Дубликаты/конфликты не замалчиваются.
Поле comments — наблюдаемый счётчик источника; его разность не равна
новым публикациям и не позволяет восстановить распределение 1–5★.

WB `rating` и `commentsvaluation` могут различаться: хранить оба поля.
MPSTATS различает округлённый и дробный рейтинги в справке о товарах;
в официальном справочнике REST название commentsvaluation описано иначе.
Поэтому не объявлять точное соответствие всех версий полей установленным
по одному примеру; в выводе остаются оба исходных показателя с названием.
Источники: [справка MPSTATS](https://wiki.mpstats.io/Wildberries/Категории/Товары),
[официальный репозиторий MPSTATS](https://github.com/mpstats-io/claude-code-skills/blob/main/mpstats/references/wb-categories.md).

## Дополнительные пути

### Публичный источник WB — проверен чтением

Карточка CDN подтверждает nm_id → imt_id. Resolver
feedback-bt.wildberries.ru/feedback/api/v2/host выбирает хост
для feedbacks/v2/{imt_id}. Ответ содержит датированные отзывы с ID,
productValuation, createdDate, updatedDate, excludedFromRating,
распределение звёзд и текущие счётчики. Есть gzip-сжатие.

Ответ может объединять несколько артикулов: записи фильтруются по nmId;
семейные totals и рейтинг не переносятся на отдельный SKU. Распределение
звёзд и другие счётчики не всегда сходятся, поэтому полнота не утверждается.
Текущее исключение из рейтинга не доказывает исключение в прошлом.
Модуль wb_public_review_source не возвращает текст, имена, фотографии
или идентификаторы пользователей. Публичный источник неофициальный и
может измениться. Идея проверена по исходникам и реальным ответам, а не
по заявлению о популярности: [автор реализации](https://github.com/shndo1337/wildberries-mcp).

### Официальные кабинеты — документировано, доступ не подтверждён

У владельца пока нет предоставленного агенту доступа к трём кабинетам WB
и трём Ozon. Наличие ключа MPSTATS не предоставляет ключи этих кабинетов.
MPSTATS lk_wb_card_table возвращает 403; lk_ozon_cabinets сообщает об
отсутствии подключений. Прямая авторизованная выгрузка seller-архива не
выполнена. Это ограничение доступа, а не доказательство отсутствия методов.

WB: список отвеченных/неотвеченных отзывов и отдельный архив. Архив включает
оценки без текста и фото; нужны все страницы, фильтр артикула, ID и даты.
[Официальная документация WB](https://dev.wildberries.cn/docs/openapi/customer-communication).

Ozon: с апреля 2026 опубликованы методы /v2/review/list и /v2/review/info;
не копировать устаревшие v1-примеры без проверки. [Обновление Ozon](https://dev.ozon.ru/news/695-Obnovleniia-v-metodakh-dlia-raboty-s-otzyvami-i-voprosami-v-Seller-API/).
Точная актуальная схема v2 не получена напрямую с сайта документации:
копия OpenAPI на GitHub является подсказкой для будущей проверки, не
доказательством рабочего подключения.

Условия доступа зависят от способа подключения. [Кейс Spix на сайте Ozon](https://dev.ozon.ru/case/392-Keis-Spix-Kak-avtomatizirovat-rabotu-s-otzyvami-i-chatami-v-Magazine-prilozhenii-Ozon/)
описывает действующую интеграцию отзывов через OAuth. [Ответ модератора Ozon](https://dev.ozon.ru/community/2235-Seller-API-Upravlenie-otzyvami/)
сообщает об отличии условий публичных приложений; это не гарантия доступа
для нашего подключения и не основание покупать подписку без проверки.

Публичный Ozon-парсер не принят как полный исторический источник: прямое
чтение с сервера получило перенаправление/защиту; браузерный обход не
настраивался. [Автор парсера](https://github.com/Lueur3/ozon-reviews-parser)
документирует ограничения глубины хронологической выборки. Ни платный
сервис, ни чужой проект не доказывают полноту нашей выгрузки без проверки.

## Воспроизводимый запрос из checkout

`scripts/remote/msp_rating_history_cli.py --marketplace wb|oz --sku SKU
--from YYYY-MM-DD --to YYYY-MM-DD --review-date YYYY-MM-DD --json`

Дату --review-date брать из реестра. Остальные собственные даты передавать
повторным --own-review-date. Обычный анализ собственной серии продолжает
использовать прежние равные окна, а произвольный запрос истории — явно
заданный период до последнего доступного дня. Это два режима, не подмена
готовых формул. Длинные периоды разбиваются на части с общим лимитом
24 чтения, включая проверку квоты. Слишком большой запрос отклоняется
до чтения источника. Ответ содержит время получения и хеш исходного
ответа, пропуски дат и явное отсутствие полных исторических итогов.

Установка, расписание и слияние не выполнены. Запуск из checkout не
доказывает подключение к установленному русскому отчёту Hermes.
