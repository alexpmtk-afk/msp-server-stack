## Новый модуль

\`apps/msp_self_analytics/peer_evidence.py\` предоставляет \`evaluate_peer_evidence(own, candidates, as_of=...)\` — чистую функцию без сетевых вызовов и записи данных.

Для собственной карточки и каждого кандидата раздельно требуются:
- \`subject\`: предмет товара
- \`intended_use\`: подтверждённое назначение
- \`dimensions_mm\`: **три числовых размера в миллиметрах**, не текст вида «400x300x800»
- \`material\`: материал
- \`package_units\`: количество товарных единиц в упаковке

Для каждого из этих полей отдельно требуется \`evidence[field] = {source_type, source_ref, observed_on}\` с корректной датой наблюдения не позднее даты анализа и не старше заданного окна (по умолчанию 90 дней). Само присутствие метаданных источника НЕ доказывает подлинность или независимость данных.

**Правило без выдумывания:** отсутствующие характеристики или источник → \`OWN_EVIDENCE_INCOMPLETE\` / \`PEER_EVIDENCE_INCOMPLETE\`; расхождения → \`STRUCTURED_FIELDS_DIFFER\`; полное совпадение → только \`MATCHED_FIELDS_REVIEW_REQUIRED\`, с обязательной отдельной проверкой специалистом, а **не** автоматическое подтверждение аналогов.

Жёсткий лимит — максимум 20 кандидатов. Результаты не включают идентификаторы карточек, названия, значения характеристик, адреса источников, цены и приватные подробности. \`verified_comparator_count\` **всегда 0**, пока не существует отдельной независимой процедуры верификации с задокументированным решением.

## Ограничение буквального сравнения

Полное совпадение размеров в этом модуле — **строгая проверка равенства**, не коммерческое правило эквивалентности. Товары с разными размерами, но одинаковым назначением могут оказаться аналогами; пока они направляются на ручную проверку, а не объявляются несопоставимыми навсегда. Нельзя выводить автоматический ценовой порог, эквивалентность материалов, вес признаков или оценку качества без утверждённых источников и формул.

## Следующий практический этап

1. Найти/подтвердить **действующий источник структурированных характеристик** для своих товаров и кандидатов MPSTATS, не подменяя его свободной генерацией описаний.
2. На 1–2 товарах только на чтение заполнить эту схему с происхождением каждого значения. Если источник неполон — сохранить \`UNKNOWN\`, а не выдумывать.
3. Подключить к историческому пакетному отчёту только после отдельной приёмки качества. Проверенные конкуренты должны иметь историю за *те же* календарные периоды, нормализацию по дням наличия и отсутствие причинных утверждений.
4. Сохранить связь с будущими блоками модели и экономики: экспертная оценка продукта, реклама и полная прибыль — отдельные метрики, которых этот фильтр сам не вычисляет.

Серверные службы Hermes, SQLite и торговые карточки остаются без изменений. Никаких инструкций по созданию неаутентичных заказов или отзывов данный модуль не предоставляет.
