# Нестоимостной анализ: принятые и неизвестные источники

## Разделение метрик
- MPSTATS sales — оценочные заказы. Изменение интенсивности по days_in_stock описывает провайдерский ряд, не независимый очищенный спрос.
- Самовыкупы учитывать отдельно. Собственная лента QRsite WB — первичная сверка по marketplace/store/SKU/датам. Полнота пагинации не доказывает полноты исходной загрузки; отсутствие строк не доказывает нулевой спрос или ошибку MPSTATS. Не связывать разные даты без ID.
- Точное число новых 4–5★ требует подтверждённого датированного распределения/четырёх счётчиков. Средняя оценка и число отзывов для восстановления распределения недостаточны.
- Накопительный счётчик: только чистая разность между сопоставимыми датами, не число новых публикаций. Placeholder строки daynum=0 не наблюдения. rating=0 не рейтинг 0★ и не база для прироста на 5 баллов.

## Проверенные MCP контракты и ограничения
wb_sku(comments) вернул список comments с date, valuation, text и last_request. Метод не фильтруется d1/d2. Нет total/пагинации/доказанной полноты. Адаптер считает только полученные записи в окне, не объявляет их всеми новыми отзывами или независимыми покупателями. Кэш может устареть до конца окна.

wb_sku(by_period) возвращает JSON-массив дневных объектов с data, rating, comments и прочими метриками. Порядок не гарантирован. Код сортирует по датам, сохраняет дубликаты/placeholder как ограничения. Наблюдаемая разность comments не принимается за точное число новых положительных отзывов; нет четырёх счётчиков рейтингов и распределения по звёздам.

lk_wb_card_table(type=articles,period_type=90days) реально проверен после выбора нужного кабинета, получил 403 «Нет доступа». Прежний scope восстановлен. Для отчёта это UNKNOWN, не ноль и не отсутствие новых отзывов. Чистый dated_review_activity готов принимать проверенный дневной ряд, но запрещено подставлять by_period.comments в new_reviews без подтверждения семантики.

## Рабочий маршрут
Существующий msp_self_sku_report_cli: SQLite mode=ro -> существующий план контрольных дат -> full по равным завершённым окнам -> comments + by_period, если остался бюджет -> own WB feed по точным окнам -> существующая сборка + nonfinancial_outcome + review_source_adapter -> русский текст. Все контрольные даты отдельно, день T исключён, до 90 дней. MAX_READS=24 сохраняется; новые обзоры имеют приоритет над необязательным keywords. Данные и источники не смешивать. Нет новых расписаний или Telegram Gateway; нет маркетплейс-записей. Денежная окупаемость отложена и не условие готовности.

Чистые модули dated_rating_dynamics, dated_review_activity, nonfinancial_outcome и peer_history_context установлены вместе с адаптером. Готовность чистых формул не доказывает доступность отсутствующих полей. Предварительные конкуренты не являются подтверждённой контрольной группой.

Реальные коммерческие ответы и тексты отзывов сохраняются только в приватном локальном отчёте, не в этом репозитории. Тесты синтетические. Состояние VPS подтверждать deployment manifest/SHA-256 и настоящим запуском CLI, не наличием исходников на GitHub.
