## 2. Доступность необходимого контекста

Следующие статусы строго различаются:
- `LIVE_CONFIRMED`: был независимый сквозной тест в реальном REMOTE;
- `CODE_PRESENT`: инструменты/схемы найдены в репозитории, текущий runtime и права не проверены;
- `PRIOR_PROBE`: есть датированный прошедший тест, но его нельзя переносить на другие методы или на сегодняшний доступ;
- `MISSING_OR_UNVERIFIED`: пока не доказано, что данные получаются в нужном разрезе и качестве.

| Данные для аналитика | Предпочтительный источник | Статус | Что сделать |
|---|---|---|---|
| Идентичность и наименование своего SKU | `product_listing`, `v_product_catalog` / экспорт МСП | LIVE_CONFIRMED | Проверить сопоставление с ID WB/Ozon |
| Завершённые и запланированные самовыкупы | `self_purchase`, `v_self_purchase`, `v_self_purchase_plan` | LIVE_CONFIRMED | Оценить полноту истории, дать явный флаг «не органическая продажа» |
| История бизнес-изменений цен | `price_event` / `v_price_history` | LIVE_CONFIRMED для объёма; контент исторически проверен | Сопоставить с фактической ценой покупателя и региональными скидками |
| Собственные WB заказы и продажи/возвраты | `marketplaces-mcp-ru`: `wb_stats_orders`, `wb_stats_sales`, `wb_fetch_all` | CODE_PRESENT | Read-only свежая контрольная выборка по конкретному кабинету, периоду, nmId |
| Собственные WB остатки | `wb_analytics_stocks_wb_warehouses`, `wb_analytics_warehouse_remains` | CODE_PRESENT | Проверить реальные поля и разницу `available`/`in-transit` |
| Собственные Ozon заказы и фактические отправления | `marketplaces-mcp-ru`: Ozon FBO/FBS postings; semantic `OZON_ORDERS` | CODE_PRESENT | Проверить охват всех кабинетов, связь order/posting/SKU, не путать заказ и продажу |
| Собственные Ozon остатки | `ozon_stocks_info`, `ozon_turnover_stocks` | CODE_PRESENT | Проверить FBO/FBS, available/reserved, ежедневный исторический ряд |
| Собственная Ozon экономика и цена | `ozon_finance_accrual_by_day`, `ozon_prices_get` | CODE_PRESENT | Проверить валюты, затраты, издержки, sku↔offer_id/product_id |
| Рекламная статистика WB | `core/wb_advertising*.py` и инструменты MPSTATS bidder | CODE_PRESENT + PRIOR_PROBE частичных агрегатов | Подтвердить привязку к SKU, периоды и расходы по каждому кабинету |
| Рекламная статистика Ozon | `ozon_perf_mcp` / provider API | CODE_PRESENT | Подтвердить рекламные расходы и attribution модели |
| WB рейтинг и отзывы по карточке | `wb_get_api_feedbacks` / MPSTATS WB SKU | CODE_PRESENT, точная история UNVERIFIED | Периоды, количество оценок, органические отзывы/обновления |
| Ozon отзывы | `ozon_list_9` и рейтинг продавца | CODE_PRESENT, доступ UNVERIFIED | Проверить ограничение подписки, возможный 403, отличать рейтинг продавца от рейтинга SKU |
| Конкуренты WB: SKU/категория/продажи/цена | MPSTATS WB external `wb_sku`, `wb_category`, niches | PRIOR_PROBE для схемы ответов на 08.10 | Сопоставимость, фактическая дата данных, качество и ограничения квоты |
| Конкуренты Ozon: SKU/категория/продажи/цена | MPSTATS Ozon external `ozon_sku`, `ozon_category` | PRIOR_PROBE для схемы на 08.10 | Подтвердить актуальность/историю, сравнимые размер/модификацию/комплект |
| Рекламная видимость конкурентных карточек | MPSTATS search/ranking/bidder | MISSING_OR_UNVERIFIED для сквозного ряда | Отделять органическую выдачу и рекламные места, не заявлять отсутствующую историю |
| Экспертная оценка сотрудника | Будущий внутренний журнал | MISSING_OR_UNVERIFIED | Схема: автор, дата, SKU, текст/категория оценки, версия |
| История принятых решений и причин отказа | Будущий журнал решений | MISSING_OR_UNVERIFIED | Создать отдельный аналитический слой после согласования |
| Причинный эффект самовыкупов | Нужны независимые продажи + сопоставимая контрольная группа | MISSING_OR_UNVERIFIED | Никаких причинных выводов из одних строк реестра |
| Прогноз органических продаж/прибыли | Производные формулы при наличии проверенных данных | NOT_IMPLEMENTED | Не прогнозировать численно, пока нет базовой истории и backtest |

## 3. Данные, которые НЕЛЬЗЯ считать подтверждёнными

1. 90/5/5 и 80/20 из совещания — оценочные проценты, не модельные коэффициенты.
2. `purchase_date` из самовыкупов ≠ дата продажи обычному покупателю; `review_url` ≠ подтверждение факта публикации отзыва.
3. `first_seen_at` каталога ≠ дата первого появления товара в продаже на площадке.
4. `wb_stats_orders` ≠ завершённая продажа; Ozon `order_number` ≠ уникальное отправление.
5. Внешние продажи MPSTATS — оценки аналитического поставщика, не прямой кабинет конкурента.
6. Медиана конкурентов без проверки аналогичности продукта — ненадёжная величина.
7. Доступность инструмента в GitHub и MCP catalog не гарантирует действующий токен, доступ к кабинету или свежие данные.
8. Отсутствие истории дневных остатков/рейтинга/рекламы нельзя компенсировать выдуманными постоянными коэффициентами.

### SELF-01B — собственные продажи и остатки

Провести `read-only` smoke по одному WB и одному Ozon SKU из существующего каталога (без публикации SKU в открытом GitHub). Для обоих запросить контрольную дату/диапазон и подготовить структурную ведомость: поле, единицы, дата данных, кабинет, ключ соединения, доступность и источник. Не выгружать PII или токены. Проверить возвраты/отмены и признаки реальной доступности.

### SELF-01C — MPSTATS: прямые конкуренты

Выполнить сначала `account_limits`, затем маленькие адресные read-only пробы WB/Ozon `*_sku` / `*_category`, не проводить массовый сбор. Проверить фактическую сопоставимость характеристик, цену, продажи, отзывы, рекламную видимость и временные границы. Сохранить только схемы/агрегаты без коммерческих значений в публичный репозиторий.

### SELF-01D — факты, ограничения и итоговый контракт

Свести собственные и внешние поля в один реестр показателей (формула, единицы, авторитетный источник, свежесть, ключ, условия NULL, статус верификации). Запретить переход к неограниченному автопарсингу и к прогнозам, пока нет подтверждённой истории собственных независимых продаж.
