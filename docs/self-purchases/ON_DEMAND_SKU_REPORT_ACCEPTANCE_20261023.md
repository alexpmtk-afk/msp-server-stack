# МСП Самовыкупы — отчёт по произвольному SKU, 23.10.2026

## Назначение и неизменяемые правила
Исторический аналитический модуль по первоначальной концепции совещания 21.10.2026. Один завершённый ряд `self_purchase` — одна записанная операция; `quantity` — повторяющийся план всей карточки, его нельзя суммировать. Контрольная дата — `review_date`, не `purchase_date`. Для каждой даты отзыва сравниваются равные завершённые окна ДО первого события и ПОСЛЕ текущего до 30 дней, ограниченные следующим событием. Отсутствующие поля — `UNKNOWN`, оценки MPSTATS не подтверждают оплаченные органические продажи и тем более причинность. Отдельный общий итог серии не заменяет поэтапный анализ.

## Проверенная локальная точка входа Hermes
`/home/hermes/.hermes/skills/productivity/msp-self-purchases/scripts/msp_self_sku_report_cli.py`

Для запроса владельца достаточно **одного цифрового SKU**: `python3 <локальный файл> --sku <числовой SKU>`. Магазин и маркетплейс определяются автоматически **по существующей таблице сопоставлений `product_listing`** в SQLite `mode=ro`. При нескольких карточках с одинаковым SKU система выбирает единственную карточку с зарегистрированной историей `self_purchase`, не объединяя записи разных магазинов. Если несколько вариантов остаются правдоподобными, возвращает `STORE_DISAMBIGUATION_REQUIRED` или `MARKETPLACE_DISAMBIGUATION_REQUIRED`; `--marketplace wb` и `--store <магазин>` служат только для явного уточнения. Поиск по внутреннему артикулу/названию для подстановки SKU запрещён. При отсутствии в каталоге — `SKU_NOT_IN_PRODUCT_CATALOG`. По Ozon CLI отвечает `OZON_PROVIDER_NOT_READY`: отдельный исторический источник для Ozon пока не проверен; подставлять WB запрещено. При количестве контрольных точек/окон выше защитного лимита возвращается явный отказ вместо обрезания серии. Вызовы сторонних инструментов ограничены `account_limits` и `wb_sku(full)`.

CLI возвращает отчёт в stdout, а не отправляет сообщения самостоятельно. Hermes может прочитать stdout и представить результат пользователю в уже существующем чате, с сохранением маркировки источников. Он не выполняет торговых действий. **Фактический диалоговый маршрут Telegram → Hermes → запуск CLI → Telegram-ответ ещё не прошёл независимую приёмку**; успешное серверное исполнение CLI его не доказывает. Сам Gateway для установки не перезапускался.

## Дальнейшая приёмка
1. В авторизованном чате Hermes попросить аналитический отчёт по одной **уже зарегистрированной** карточке WB, указав только её SKU (магазин Hermes определяет по каталогу автоматически).
2. Убедиться, что Hermes самостоятельно вызвал локальный CLI с корректными аргументами и ответил в ту же ветку чата, без отправки частных данных в GitHub.
3. Проверить соответствие отчёта реальным числам MPSTATS, плану карточки и всем датам отзывов; затем зафиксировать `TELEGRAM_ON_DEMAND_PASS` только после фактического успешного ответа.

Запрещено создавать фиктивные покупки, отзывы или автоматизировать влияние на рейтинги. Анализ исключительно ретроспективный.
