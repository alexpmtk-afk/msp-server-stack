## Назначение и поля основной вкладки

Это журнал поступивших замечаний и их обработки, а не только подтверждённых
производственных дефектов. Одна содержательная строка — одно зарегистрированное
обращение. Повтор одного артикула не основание объединять жалобы.

| Колонка | Значение |
|---|---|
| A | ✅ — товар подавался на производство в указанном году; ❌ — такого заказа по проверке формулы не найдено. Не факт выпуска, не статус исправления. Сейчас год в заголовке 2026. |
| B | Маркетплейс и юридическое лицо/кабинет, сохранять исходное название |
| C | Производство: Лазер, АНТ, Швейка, Дерево |
| E | Внутренний артикул, не SKU маркетплейса |
| F | Наименование |
| G | Дата поступления отзыва/вопроса/рекламации, не дата покупки и не гарантированная публичная дата отзыва |
| H | Номер заказа, может отсутствовать |
| I | Жалоба покупателя, обычно копия сообщения |
| J | Категория жалобы |
| K | Источник: отзыв, вопрос, рекламация, брак без рекламации |
| L | Записанный статус производства |
| M | Дата статуса; пустую дату не заменять датой загрузки |
| N | Комментарий к статусу |

В расшифровке оговорка: категория названа G, но в реальной таблице это J.
Написание «АМТ» в речи относится к АНТ по фактической структуре вкладки.
Часть статусов L/N вычисляется формулой поиска по тексту жалобы; возможны
неоднозначные совпадения. Исходные вычисленные значения сохраняются.

## Категории: смысл, не доказанная причина

- Ржавеет, Не комплект, Проблемы с скотчем — записанная проблема.
- Транспортировка — проблема доставки/перевозки, отнесённая сотрудником
  к стороне маркетплейса; это не независимое доказательство виновности.
- Упаковка — возможность улучшить собственную упаковку для сохранности товара.
- Не функционален — не выполняет ожидаемую/заявленную функцию.
- Скол, непокрашен — возможны перевозка или покраска на производстве;
  автоматически не выбирать причину.
- Брак производства — записана производственная некондиция.
- Пересорт — покупателю пришёл другой товар/вариант.
- Пончо, Поисковые грабли — товарные группы проблем, не виды дефекта.
- Неверный контент — описание/размер/материал расходятся с фактом.
- Другое сохраняется, но не подменяет конкретную категорию.
Сохранять составные категории целиком: запятая внутри «Скол, непокрашен»
не означает две разные категории.

## Статусы и вторая вкладка

«Решено» — производство записало устранение; комментарий описывает изменение.
«Передано на производство» — передано, ещё не устранено.
«Зависло» — решение не завершено/приостановлено.
Пустой статус — неизвестно; не считать автоматически решённым или зависшим.
Статус журнала — учётное свидетельство, не независимая проверка каждого изделия.

Вкладка для Лазера автоматически отбирает из основной строки Лазер/АНТ:
A — маркер года, B — артикул, C — название, D — дата, E — жалоба,
F — статус, G — комментарий производства.
Это НЕ дополнительные жалобы; аналитическое количество берётся только
из основной вкладки. Статусы второй привязываются по внутреннему артикулу,
дате поступления и точному тексту. При повторных ключах/расхождениях
не выбирать первую строку. Связь отмечается как неоднозначная/конфликтная,
исходные статусы обеих вкладок остаются доступны.

## Использование для анализа

Сначала сопоставить marketplace+store+SKU с внутренним артикулом по product_listing.
Нельзя считать жалобы всех кабинетов жалобами выбранной карточки. Если сопоставление
названия кабинета неизвестно — показать неопределённость, не угадывать.
Вывести: какие проблемы встречались, даты, категории, статусы, записанные меры.
Сравнивать до/после только по дате поступления и подтверждённой дате изменения
производства. Дата исправления, дата нового выпуска и дата публикации отзыва
не взаимозаменяемы. Отсутствие жалоб в журнале не доказывает отсутствие брака.
Число жалоб не равно проценту брака без сопоставимого числа проданных единиц.
Рекламации и негативные оценки могут пересекаться — не суммировать без связи.
Рейтинг 1–5★ получать отдельным действующим источником оценок.

## Даты наблюдения изменений — дополнение владельца

При каждом успешном ежедневном обновлении фиксируются:
- когда запись впервые замечена агентом;
- прежний и новый статус, дата и время обнаружения изменения;
- изменение комментария отдельно от изменения статуса;
- предыдущее наблюдение: изменение могло произойти между двумя загрузками.

Дата обнаружения по Москве — наблюдение агента, НЕ фактическая дата решения,
исправления изделия, выпуска партии, поступления товара покупателю или публикации
отзыва. Исходная дата статуса M сохраняется отдельно и не заполняется агентом.
В Google-таблицу агент ничего не дописывает.

Уже загруженные статусы становятся исходной базой: «Решено» при первой загрузке
не получает выдуманную дату решения. Ранее сохранённые значения используются
только как подтверждённая исходная точка наблюдения, без восстановления
неизвестных прежних переходов. Новая запись получает дату первого обнаружения,
а не предполагаемую дату создания.

Связь ведётся по содержательному ключу, а не номеру строки. Перестановка строк
сама по себе не меняет статус и не создаёт новое обращение. Повторные ключи,
пропущенные идентификаторы, исчезновение/возвращение записи или исправление
полей ключа не дают права угадать переход. После разрыва наблюдения используется
новая исходная точка; смена статуса в промежутке не утверждается.
Очищение статуса тоже записывается, но не означает «Решено».
Одновременные изменения статуса и комментария сохраняют оба старых/новых значения.

Таблицы: defects_observed_entity (первое/последнее наблюдение и последние
обнаруженные изменения), defects_observed_current (связь с текущими строками
и качество сопоставления), defects_status_event (история событий).
При query поле status_observations относится к надёжно связанному статусу:
для металла — к вкладке Лазера, для остальных — к основной. При конфликте
между вкладками/неоднозначной связи дату изменения эффективного статуса
не назначать. main_status_observations сохраняет историю исходной основной строки.
Истории двух вкладок не являются двумя отдельными жалобами.

В анализе писать «смена статуса замечена ДД.ММ.ГГГГ» или «к этому дню в журнале
уже стояло Решено», а не «брак устранён ДД.ММ.ГГГГ».
Сравнение жалоб до/после этой даты — приближённое по наблюдаемому рубежу,
не доказательство эффекта исправления или самовыкупа.

## Хранение и обновление

База: /opt/mcp/data/msp/defects-feedback/catalog.sqlite3.
Текущие данные: defects_current (только основная популяция).
Исходные строки обеих вкладок: defects_source_row;
история изменений: defects_row_revision; связи: defects_link; запуски: defects_run.
Полные снимки только двух вкладок, включая формулы, находятся в snapshots.
Строки с одним техническим нулём артикула и пустыми остальными полями
не являются обращениями; их исходные значения остаются в снимке.
Номера физических строк — происхождение, не стабильные ID жалоб при сортировке.
Перемещение строк не доказывает появление новых обращений.
Исчезнувшие строки помечаются неактуальными, история не удаляется.
При ошибке чтения предыдущая успешная база сохраняется. Падение числа строк
более чем на 20% требует проверки; не выполнять массовое удаление автоматически.
Форматы даты ДД.ММ.ГГГГ, ДД.ММ.ГГ и с временем читаются; исходное значение сохранено.

Ежедневно 08:30 Europe/Moscow. Persistent=false: пропуск при выключенном
сервере не вызывает неожиданную загрузку при включении; последняя дата видна
в last-success.json. Не менять соседние расписания.
Исполнитель использует существующий task-visibility/run.py, проверку результата
и реальную квитанцию; отдельная модель и новый наблюдатель панели не требуются.
