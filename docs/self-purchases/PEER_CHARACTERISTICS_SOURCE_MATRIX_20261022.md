## Вывод без догадок

Существующих *подтверждённых* ответов MPSTATS пока достаточно для предварительного поиска и исторических описательных показателей, но **недостаточно для достоверной группы сопоставимых товаров**. В новой проверке `peer_evidence.py` отсутствие структурированных полей и датированных ссылок на их происхождение означает `OWN_EVIDENCE_INCOMPLETE` или `PEER_EVIDENCE_INCOMPLETE`.

Нельзя автоматически извлекать габариты из названия, придумывать материал по фотографии, объявлять внешние оценки историческими либо утверждать, что товары одинаковы по комплектации из-за близких цен. Даже полное совпадение известных атрибутов требует отдельной независимой проверки специалистом.

## Практический маршрут

1. Для **собственных** карточек исследовать уже разрешённые справочники 1С/МСП и официальный WB Content API, **только если существует одобренный защищённый доступ**. Не копировать токены в GitHub или Telegram.
2. Для **чужих** товаров искать законно доступные и разрешённые данные о фактическом назначении/габаритах/материале/комплектности; подтверждать происхождение каждого свойства; `UNKNOWN` оставлять `UNKNOWN`.
3. На 1–2 SKU проверить полноту полей, прежде чем запускать массовый набор и историческое сопоставление.
4. Сравнение динамики продаж конкурентов считать описательным; для причинных выводов нужны сопоставимость, изменения наличия, цены, рекламы, сезонности и другие факторы.
5. Перейти к экономике и объяснимой рекомендации Hermes только после дополнения источников. Текущий фильтр ничего не меняет на маркетплейсах и не предназначен для организации неаутентичных отзывов.
