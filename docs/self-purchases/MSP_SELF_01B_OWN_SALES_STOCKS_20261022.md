## 2. Разделение фактов и неизвестного

| Показатель | Статус | Контракт |
|---|---|---|
| Список своих карточек по marketplace+store+sku | `LIVE_SQLITE_CONFIRMED` | DB `product_listing` |
| Октябрьские и сентябрьские продажи, количество | `SHEET_READ_VERIFIED` | Google `продажи мп компакт` |
| Октябрьские заказы, количество | `SHEET_READ_VERIFIED` | Google `заказы` |
| FBS/FBO остатки в выгрузке | `SHEET_READ_VERIFIED` | Google `продажи мп компакт`, мгновенный срез с пока не доказанной частотой |
| Исторический дневной `sellable` остаток | `NOT_VERIFIED` | Нужна последовательность снимков или официальный API |
| Верификация API WB продаж и остатков | `CODE_PRESENT_NOT_RUNTIME_VERIFIED` | `wb_stats_sales`, `wb_analytics_stocks_wb_warehouses` |
| Верификация API Ozon продаж и остатков | `CODE_PRESENT_NOT_RUNTIME_VERIFIED` | `ozon_analytics_data`, `ozon_stocks_info` |
| Отнесение продаж к «органическим» | `NOT_VERIFIED` | Нужен явный канал привлечения, иначе `UNKNOWN` |
| Возвраты/отмены, комиссии, расходы по конкретному SKU | `NOT_VERIFIED` | Не считать прибыль без этих компонентов |

В публичном [marketplaces-mcp-ru](https://github.com/alexpmtk-afk/marketplaces-mcp-ru) код API-инструментов есть, но их не следует считать установленными на сервере Hermes только по GitHub.

## 3. Метрики: формулы, а не константы

- `sales_qty(period, sku)` = агрегированное количество подтверждённых продаж из источника за **точно заданный** период, с явно выбранной семантикой возвратов (сейчас уточняется).
- `orders_qty(period, sku)` = отдельное количество заказов; **не равно** `sales_qty`.
- `sellable_stock(t, sku)` = подтверждённый доступный остаток по состоянию на время `t`; данные одного экспортного среза не образуют ряд.
- `sales_per_available_day` = `completed_sales_qty / days_with_confirmed_sellable_stock`. **Пока не рассчитывать**: знаменатель не подтверждён.
- `growth_vs_previous` = `current_comparable_sales / previous_comparable_sales - 1` только для сопоставимых по продолжительности периодов и при положительном предыдущем значении; иначе `UNKNOWN`, не бесконечность и не статический процент.
- `gross_margin_contribution` рассчитывается из цены покупателя, фактической комиссии, логистики, рекламы, себестоимости и возвратов **после подтверждения всех компонент**.
- История `self_purchase` — отдельный тип событий, не прибавлять автоматически к органическим продажам и не использовать для оценки причинности без контроля.

Каждая метрика обязана иметь `source_id`, `source_updated_at`, `period_start/end`, `source_type`, `marketplace/store/sku`, `unit`, `status` и `missing_reason`; без этого вывод не считать доказанным.

## 4. Реализованный безопасный QA-модуль

Исходник: [`apps/msp_self_analytics/source_quality.py`](../../apps/msp_self_analytics/source_quality.py). Тесты: [`tests/test_msp_self_analytics_source_quality.py`](../../tests/test_msp_self_analytics_source_quality.py).

- Работает **без API и сети**, только с тремя заранее авторизованными CSV-снимками (`артикулы`, `продажи мп компакт`, `заказы`).
- Не пишет в SQLite и не меняет исходные таблицы.
- Принимает параметр `--period`, поэтому не подменяет формулы статичным «октябрь»; `--previous-period` опциональный.
- Проводит стыковку по тройному ключу, учитывает пропуски/дубли, отдельно нули и `null`.
- В отчёте **только агрегаты**, не выводятся SKU, названия, суммы заказов и коммерческие строки.
- Отказывается утверждать полноценную чистоту источника при проблемах ключей.

**Статус:** модуль подготовлен и протестирован на фиктивных данных в репозитории, но **не установлен на REMOTE и не обрабатывал там реальные CSV**. Предшествующая интерактивная проверка Google Sheet 22.10 — отдельное read-only доказательство.

## 5. Следующая последовательность

1. Утвердить безопасный канал поставки доступных Google Sheets снимков на REMOTE (не требуя от владельца вручную переносить пароли). Желательно использовать существующий слой защищённой выгрузки CSV для МСП; не публиковать полную sales/order таблицу в GitHub.
2. Применить `source_quality.py` к отдельным CSV снимкам и сравнить строго агрегированную статистику с настоящим чтением Google Sheets; проверить ключи на 1 WB и 1 Ozon карточке без публикации SKU.
3. Разобраться с 12+20 карточками без компактной истории: действительно новые, архивные, отсутствующие в подключённой выгрузке или проблема сопоставления.
4. Подключить официальный WB/Ozon MCP в **отдельном read-only профиле**, используя штатное хранилище секретов и лимиты; не переключать глобально активный кабинет и не копировать токены в GitHub.
5. Затем провести по одному разрешённому прямому live read для WB/Ozon и сравнить доступность с вторичным Google-источником.
6. Только после подтверждения качества собственных данных расширять контекст конкурентами MPSTATS и первыми формулами оценки.

**Итог этапа:** собственные данные для исследования **найдены**, а реальный доступ Hermes к API кабинетов — **пока нет**. Первый аналитический модуль можно строить поверх уже существующего источника, но нельзя выдавать отчёты на его основе за подтверждённый прогноз органических продаж.
