# MSP-SELF-03 — финальный рабочий порядок поиска конкурентов, 22.10.2026

**Статус:** принято направление владельца для дальнейшей реализации. **Исследовательский этап поиска прекращён**: результаты собраны в [протоколе реальной приёмки](MPSTATS_SAME_SOURCE_CARD_CONTENT_ACCEPTANCE_20261022.md). Не проводить бесконечные поиски «идеального идентичного» товара. Теперь приоритет — MSP-SELF-05/06 (формулы, экономика, решение Hermes).

## Что владелец действительно требует

Искать **максимально близкие по назначению и рыночному контексту**, но не обязательно буквально идентичные изделия; достаточно обоснованной сопоставимой группы для изучения спроса/цен/конкуренции. Жёсткое равенство всех атрибутов **не требуется**. Совпадения/отличия сохраняются как объяснения и неопределённость, а не как автоматический отказ каждому кандидату.

Оригинал: приватные `MEETING_TRANSCRIPT_2026-10-21.md` и `INITIAL_VISION_V1_2026-10-21.md`. Рабочие нормы: `PROJECT_COMPASS.md`, `SERIES_TARGET_PER_ROW_CORRECTION_20261022.md`. Никаких повторных коррекций исходного оригинала.

## Окончательно выбранный базовый алгоритм

1. Получить `marketplace + store + marketplace_sku` из существующего SQLite `self_purchase`; выбирать реальные `completed` исторические записи, не планы. SKU не искать в 1С.
2. Получить свою карточку из того же MPSTATS: `wb_card_content(sku=<строка>)`, характеристики в `options[{name,value}]`. `wb_sku` для статистики принимает **числовой** SKU.
3. Основной поиск WB: `wb_similar(family="identical", path_value=<строковый SKU>, report="products")`. Поскольку это найденные алгоритмом кандидаты, название режима не доказывает действительную идентичность.
4. Если кандидатов мало/недостаточно по назначению и свойствам, расширить выборку через `family="similar"`. `identical_wb` в испытанном примере дал ноль и **не является обязательным**; `in_similar` пока не проверен и не нужен для этой версии.
5. Ограничить выдачу каждого режима восемью кандидатами **как технический лимит конкретного запроса**, убрать повторы SKU и собственную карточку. Порядок получения от провайдера — только порядок кандидатов, а не доказательная оценка качества.
6. По выбранным кандидатам вызвать тот же `wb_card_content(sku=<строка>)`, сопоставить **назначение/предмет, категорию, функции, размеры изделия, материал, комплектацию, ценовой контекст**, отдельно отличая размеры упаковки от предмета.
7. Не отбрасывать товар только из-за несовпадения материала/размера, если может быть заменителем для покупателя. Не вводить выдуманные веса, универсальные допуски сантиметров, жёсткие статические проценты или автоматические «истинные аналоги».
8. Предоставлять Hermes группу `POTENTIAL_MARKET_PEERS` с описанием различий, пропусков и степенью уверенности; `VERIFIED_COMPARABLE` присваивать **только** после проверки назначения и рыночной взаимозаменяемости по источникам/экспертному решению. Если таких нет — числовое отношение цены к *верифицированной* медиане остаётся `UNKNOWN`. Для описательного контекста можно показывать оценочную динамику *предварительных* кандидатов с пометкой.
9. Все данные динамики — за одинаковые окна. Разделять оценочные продажи MPSTATS и подтверждённые собственные заказы, учитывать дни наличия и рекламу. Нельзя приписывать изменение продаж самовыкупам/отзывам без подтверждённой причинной оценки.
10. Для Ozon тот же **бизнес-алгоритм**, но методы поиска похожих WB не копировать буквально. Режимы Ozon проверяются по фактической схеме, когда понадобится Ozon; непроверенные названия инструментов не выдумывать.

**Решение:** поиск конкурентов больше не блокирует остальную аналитическую систему. Если сопоставимых нет, система сообщает `UNKNOWN`, но продолжает анализ **собственных** реальных продаж, наличия, цены, рекламы, расходов, жалоб/качества и допустимых альтернатив. Это отдельный диагностический модуль, не подтверждённый статистический контроль эксперимента.

## На что переключаемся прямо сейчас

**MSP-SELF-05/06:** рассчитывать лишь проверяемые показатели, формулы и сценарную экономику. Первая очередь — скорость подтверждённых органических продаж за дни наличия; конверсия только при достоверных просмотрах и заказах; относительная цена — только при подтверждённой группе; денежный эффект — только с проверенной маржой, затратами и отдельно обоснованным прогнозом объёмов. При отсутствии источника выводить `UNKNOWN`, а не ноль.

Допустимые варианты: улучшить товар/описание/сервис, цену, рекламу, доступность, либо ничего не делать. Автоматизация неаутентичных заказов и отзывов **не является** действием системы. Hermes принимает решение только после осмысленного отчёта человеку; никаких действий с площадками без отдельного подтверждения.
