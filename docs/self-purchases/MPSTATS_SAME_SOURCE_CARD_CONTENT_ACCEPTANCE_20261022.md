# MSP-SELF-03 — исправление типа SKU и реальное сопоставление MPSTATS, 22.10.2026

**Актуальный подтверждённый статус: `PASS_DESCRIPTIVE_LIVE_COMPARISON`.** Технический путь «SKU из SQLite самовыкупов → MPSTATS подробности собственной карточки → MPSTATS похожие → MPSTATS подробности конкурента → сравнение одинаковых свойств» проверен на VPS и работает **без 1С**.

## Почему предыдущие отчёты ошибочно считали источник недоступным

- В прежних исследованиях №536 и №559 инструмент `wb_card_content` вызывался с числовым `sku`, и сервер возвращал `TOOL_ERROR`.
- Настоящий реестр MCP, прочитанный без бизнес-запросов [№560](https://github.com/alexpmtk-afk/msp-server-bridge/issues/560), содержит 108 инструментов. Его схемы различаются: `wb_sku` требует `sku: integer`, но `wb_card_content` требует **`sku: string`**; `wb_similar` — `path_value: string`.
- При повторе с корректными строковыми SKU [№561](https://github.com/alexpmtk-afk/msp-server-bridge/issues/561) **обе** карточки дали `PASS_STRUCTURED`. Поэтому исторические `TOOL_ERROR` больше не свидетельствуют о невозможности получения характеристик. Точное объяснение ошибки на уровне реализации провайдера не проверялось; несоответствие типа аргумента установлено.
- У обеих карточек структурированные характеристики представлены массивами `options`, где элементы содержат `name` и `value`: [проверка №562](https://github.com/alexpmtk-afk/msp-server-bridge/issues/562). На собственном товаре найдено 13 уникальных непустых наименований свойств, у внешнего кандидата — 15; nested-секции дублируют часть данных и не означают новые свойства.

## Подтверждённое текущее сравнение: два товара, один источник

[REMOTE №563](https://github.com/alexpmtk-afk/msp-server-bridge/issues/563) провёл live-тест нового `apps/msp_self_analytics/mpstats_option_comparison.py`. Публичный модуль изолирован и не делает внешних действий; private runner читает `self_purchase` через SQLite `mode=ro`, ищет один внешний SKU через `wb_similar`, получает обе карточки через **один `wb_card_content` со строковыми SKU**, сравнивает значения в памяти и публикует только обезличенные результаты.

| Группа характеристик | Итог |
|---|---|
| Тип установки | `MATCH` |
| Материал изделия | `DIFFERENT` |
| Объём (л) | `DIFFERENT` |
| Высота предмета | `DIFFERENT` |
| Ширина предмета | `DIFFERENT` |
| Комплектация | `DIFFERENT` |
| Цвет | `DIFFERENT` |
| Страна производства | `DIFFERENT` |
| Длина, ширина, высота упаковки | `DIFFERENT` по каждому |
| Вес с упаковкой (кг) | `DIFFERENT` |
| Дополнительные опции | `DIFFERENT` |
| Форма, тип ведра | `ONLY_PEER` |

**Итог по 15 выделенным полям:** 1 совпадение, 12 расхождений, 2 поля только у конкурента, конфликтующих дублей 0. Протокол защищён от выдачи SKU, названий, цен, значений свойств, токенов и текстов отзывов.

Критично: **габариты упаковки не подменяют габариты товара**. У «Высоты предмета» и «Ширины предмета» в ответе не была независимо доказана единица измерения; третьей отдельной размерности предмета по проверенным меткам нет. Одинаковая строка значения пока только строковое совпадение, не доказанная физическая идентичность.

Действуют поздние уточнения `PROJECT_COMPASS.md`, `SERIES_TARGET_PER_ROW_CORRECTION_20261022.md`. Этап — **MSP-SELF-03**, предварительная проверка сопоставимости кандидатов для описательной аналитики.

Даже полностью совпадающая сводка нынешних свойств не доказывает, что товары имели эти свойства в исторические периоды продаж, являются взаимозаменяемыми или пригодны для причинной контрольной группы. Именно этот внешний кандидат по 12 полям различается, поэтому `verified_comparable_competitors = 0`. Не подставлять такой товар как подтверждённый контроль. Ничего не утверждать о причинном влиянии записей отзывов/покупок.

## Расширенный контроль: первые пять внешних карточек

[REMOTE №564](https://github.com/alexpmtk-afk/msp-server-bridge/issues/564) проверил ещё четыре карточки после первого кандидата тем же инструментом `wb_card_content(sku: string)`. Все пять ответов `PASS_STRUCTURED`; `PASS_FIVE_PEERS_SCREENED`; `marketplace_actions=0`, `sqlite_writes=0`, `hermes_changes=0`.

| Номер кандидата (без публичного SKU) | Совпали записанные значения | Разные значения | Поле отсутствует хотя бы у одной стороны |
|---|---:|---:|---:|
| 1 | 1 | 12 | 2 |
| 2 | 1 | 11 | 3 |
| 3 | 1 | 12 | 2 |
| 4 | 2 | 11 | 2 |
| 5 | 1 | 12 | 2 |

У всех пяти расходятся **материал**, **объём**, **высота и ширина** предмета, а также комплектация. Они остаются **потенциальными кандидатами без доказанной взаимозаменяемости**; эти цифры нельзя трактовать как ранжирование качества товаров или научное доказательство неконкурентности. Отсутствующий параметр не равен нулю. Даты характерис­тик относятся к текущему снимку и не подтверждены на старые исторические периоды.

Следующая диагностика — проверить фактически объявленные режимы `wb_similar.family` для возможности более релевантного поиска: в пользовательском интерфейсе MPSTATS есть отдельные группы похожих AI и идентичных WB товаров, но доступность этих конкретных режимов в нашем MCP и их параметры **не установлены**. Не придумывать значения `family` и не выполнять непроверенные запросы. Подтверждённых контрольных аналогов по-прежнему 0.


## Дополнительные режимы поиска кандидатов: schema-first, без угадывания параметров

В реальном `tools/list` MCP [#565](https://github.com/alexpmtk-afk/msp-server-bridge/issues/565) перечислены допустимые значения `wb_similar.family`: `identical`, `identical_wb`, `similar`, `in_similar`. Описание сервера подтверждает эти названия; нюансы того, какой именно алгоритм соответствует каждому, не доказаны отдельно. В официальном интерфейсе MPSTATS существуют «Идентичные товары WB» и «Похожие товары AI», но нельзя автоматически приравнивать отдельный API enum к конкретной UI-вкладке без независимой проверки документации.

[Приватная приёмка №566](https://github.com/alexpmtk-afk/msp-server-bridge/issues/566), `PASS_ALTERNATIVE_FAMILIES_PROBED`:

| Режим `family` | Кандидаты в ограниченном ответе | Глубоко проверено через `wb_card_content` | Совпало полей |
|---|---:|---:|---|
| `similar` | 8 | 5, предыдущий опыт №564 | 1 / 1 / 1 / 2 / 1 |
| `identical` | 8 | 2 | 2 / 5 |
| `identical_wb` | 0 | 0 | нет данных |
| `in_similar` | не проверялся | 0 | неизвестно |

В режиме `identical` у одного кандидата совпали высота/ширина предмета и тип установки, но материал, объём и комплектация разошлись. У другого совпала высота, но разошлись материал, ширина и установка. Это **не подтверждённые эквивалентные товары**. Во всех проверках текущее `verified_control_peers=0`.

Результат №566 подтверждён завершённым GitHub Actions `SUCCESS`, без изменения SQLite, Hermes или маркетплейсов. Дальше не нужно подключать 1С; требуется обобщить существующий read-only адаптер для произвольных SKU из `self_purchase`, делать ограниченную выборку по доступным режимам и оставлять независимую проверку смысловой товарной сопоставимости. Текущий анализ — исследовательский, не выдавать его за работающую автоматическую рекомендацию Hermes.
