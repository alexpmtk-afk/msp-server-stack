# Единый статус автоматической обработки сигналов МСП

**Срез: 05.11.2026.** Единый вход для ChatGPT, Hermes, Codex и других подключённых агентов. Этот файл — **реестр состояния**, не замена действующих бизнес-инструкций и не разрешение менять маркетплейсы. Канонический репозиторий: `alexpmtk-afk/msp-server-stack`.

## Как читать статусы

Отдельно проверять: (1) распознавание входного сигнала; (2) согласованную бизнес-логику; (3) подготовленный код; (4) установленное на VPS; (5) подключение к действующему Gateway/процессу; (6) реальный вызов с проверкой итога. **Merged PR ≠ deployed runtime ≠ live execution.** Для уровня «работает» требуются конкретные проверяемые server logs / issue acceptance, не обещания и не наличие текстового Skill.

Общий пассивный обработчик `apps/msp_signal_notify/notify.py` распознаёт 6 типов, читает уже существующий Telegram-архив и отправляет тестовые уведомления (проектное расписание 60 секунд), без обновлений маркетплейсов. Отдельный ручной Hermes `msp-signals` и отдельный QRsite workflow SIG-032 не являются частью одного и того же исполнительного процесса. Не смешивать их статусы.

## Правило обновления общего статуса

После **каждого** изменения SIG-002/015/016/021/022/032 автор (Hermes или ChatGPT):
1. Создаёт отдельный GitHub PR с исходниками/инструкциями/тестами и обновлением **именно этой таблицы**, прикладывает точные ссылки на PR/issue/runtime evidence и дату проверки.
2. Явно пишет четыре статуса: `CODE`, `MERGED`, `DEPLOYED`, `LIVE_E2E` (PASS/FAIL/NOT_TESTED), не объявляет одно доказательством другого.
3. Не меняет `main`, не сливает PR, не устанавливает на сервер без отдельного разрешения владельца согласно [MSP_GITHUB_VPS_WORKFLOW.md](../MSP_GITHUB_VPS_WORKFLOW.md).
4. После установки проверяет фактическую версию Hermes и фиксирует проверку в GitHub, затем обновляет статус.
5. Другие чаты читают `main` этого единого файла и соответствующие актуальные справочники; **доступ к GitHub не гарантирует чтения из ChatGPT без подходящего подключения**.

## Известные несогласованности, требующие отдельного исправления

- `docs/signals/README.md` ещё содержит историческое утверждение «в SIG-002 нет даты — нет производственного заказа»; читать **только** новое правило от 27.10.
- `apps/hermes/msp_signals_skill/SKILL.md` и `REVIEWED_RULES_2026-10-05.md` называют SIG-032 только имитацией; это описание **пассивного notifier**, не всего достигнутого SIG-032. Реальные Gateway callback всё же остаются выключенными по #679.
- Для SIG-002 новый отчёт заказов может применяться для оценки количества будущей партии, а ранее утверждённое правило использует готовые `_N`. До согласования не считать их одной формулой и не менять автоисполнение цен.
