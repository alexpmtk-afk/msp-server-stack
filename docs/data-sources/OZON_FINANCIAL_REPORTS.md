## Чтение и смысл

Одинаковые источники для панели Hermes, TUI и разрешённых Telegram-чатов
одного default-профиля. Это не автоматическое слияние историй/разрешений чатов.
Не искать случайные файлы на Drive и не запрашивать root для чтения уже
открытых финансовых файлов. Исходники не менять и повторно не скачивать ради анализа.

Метод `/v1/finance/realization/posting` отдаёт месячную реализацию по отправлениям.
Это не список заказов, не все начисления/логистика/реклама, не банковская выплата
и не прибыль. `delivery_commission`/`return_commission` — структуры реализации;
не трактовать их название как полный расход доставки без справочника формул.
Сначала изучить фактические вложенные поля `item`, `order`, `delivery_commission`,
`return_commission`, `legal_entity_document`; не терять их при чтении CSV.
CSV UTF-8-BOM, разделитель `;`, вложенные JSON сохранены плюс `_raw_json`.
Ключ: кабинет + report_year + report_month + row_number. Номера строк не являются
уникальными между месяцами/кабинетами. SKU/артикулы читать как строки.
Валюта и шапка документа находятся в исходном response.json, не угадывать их.

Читать `ozon-financial-reports/GUIDE.md` и `FIELD_BINDINGS.md` перед расчётами.
Машинная карта `ozon-financial-reports/field-bindings.json` покрывает все46

Две итоговые формулы закрывающего отчёта сверены с официальным образцом XLSX.
Источники сохранены локально в `ozon-financial-reports/sources/`; происхождение,
контрольные суммы и границы проверки — `source-reconciliation.json` рядом.
Это не полная текущая спецификация позаказного API. Его total не объявлять
банковской выплатой/прибылью и не пересчитывать по универсальной формуле.

ВАЖНО: месячная реализация не даёт произвольный ежедневный срез продаж.
order.created_date — дата заказа; doc_date — дата документа, не дата продажи.
legal_entity_document.sale_date отсутствует у большинства строк. Для отдельного
дневного интервала реализации нужен другой подтверждённый источник. Прежнее
«любой интервал внутри загруженных дат» для Ozon верно только при явной роли даты:
по отчётному периоду — месяцы; по дате заказа — когорта заказов, не дневная реализация.
Не восстанавливать/исправлять total по наблюдаемому равенству: использовать фактическое
значение, отдельно показывать реализацию/возвраты и отсутствующие блоки.
