# Weekly column binding — scoped acceptance 10.11.2026

The saved current snapshots for six weekly datasets across three cabinets were exercised locally without provider calls or archive mutations. All observed source columns map explicitly to the official SalesReportsDetailedRes schema. The official YAML URL and SHA256 are in official-column-schema.json. No credentials are part of this contract.

The installed private schema-profile.json records hashes, rows/types/presence, raw-JSON/CSV equality, per-operation formula diagnostics and DAC permissions. It is intentionally not copied into the public repository. The official agencyVat column was not present in the saved headers; UI row number and separate loyalty-kVV component have no standalone local column. Neither is silently zero-filled.

Meaningful reader tests cover return direction, unallocated storage, negative deductions, unknown operation preservation, SKU/date filters, currency separation, JSON boolean serialization, checksums, duplicate identities, changed CURRENT, symlinks, absent fields and critical semantic column distinctions. Three real October 2026 queries (both document types) independently matched a separate CSV/Decimal accumulator. Four rows fail the simple payout arithmetic check; recorded actual forPay values remain authoritative, and the reason is not established.

Hermes reader/skill installation is complete. The proposed shared directory for arbitrary local applications is a separate administrative install: until its deployment.json is read back it must remain PREPARED_NOT_INSTALLED. Financial CSVs already permit world read without world write. Container/sandbox access is a separate mount constraint. No promise that arbitrary applications automatically consume the skill.

Daily reports, bank payouts, tax base, profit, fresh provider inventory and full summary reconciliation are outside this scoped acceptance. Ordinary sales/returns totals explicitly exclude corrections/compensations, which remain visible in operation_breakdown.
