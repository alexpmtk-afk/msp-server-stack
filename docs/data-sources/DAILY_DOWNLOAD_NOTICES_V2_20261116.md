## Поручение владельца

Меняются только ЕЖЕДНЕВНЫЕ сообщения, недельный формат без изменений.
Заголовок «Ежедневные отчёты за ДД.ММ.ГГГГ», затем «Загружены:», пустая
строка, Wildberries и каждое юридическое лицо с новой строки; отдельно Ozon.
Пропуски — отдельным блоком: площадка, юрлицо, дата и конкретный исход.

После первого завершённого обхода, если есть WAITING_DATA, допускается
промежуточный итог с числом выполненных проверок и временем следующей.
Не выдавать его за окончательный. Повтор того же ожидания на второй попытке
не спамит. Изменение состояния — готовность, окончательный пропуск после3
дневных проверок, технический HOLD — вызывает дополнительный ежедневный итог.
Финальный пропуск содержит ФАКТИЧЕСКОЕ число проверок и время завершения
последней по сохранённой worker receipt (mtime), не now/next_due и не догадку.
Если времени нет, его не выдумывать. HTTP429 явно обозначать как лимит API;
HOLD не называется обычным отсутствием или якобы выполненными3проверками.
Эта доработка уведомлений не меняет политику повторов загрузчика при HOLD.

Поздний успех по той же дате, включая ручную загрузку/исправление либо
покрытие проверенным недельным источником, закрывает прежний пропуск
дополнительным сообщением. При недельном покрытии писать «данные получены
в недельном отчёте; дневной отдельно не докачивался», не приписывать
несуществующую дневную загрузку. Не запрашивать старые daily ради сообщения.

Существующие SENT-сообщения и outbox сохраняются без перезаписи.
Начальное сообщение имеет старый ключ daily+дата. Последующие имеют
kind+дата+update+хеш смыслового состояния, без attempt/timestamp в хеше.
SENDING сохраняется до sender, точный ACK chat/topic/text/message_id после.
Неопределённое начальное или дополнительное отправление запрещает слепые
повторы. Уточнения включены с даты запуска16ноября: старую историю массово
не пересылать. Недельный итог доставляется после дневного финального итога;
сбор данных не останавливается из-за Telegram. Недельный текст не меняется.

## Привилегированная установка

Архив содержит только model/controller/sender уведомлений, installer,
baseline hash pins и полный MANIFEST. Launcher проверяет все6членов,
типы/пути/режимы/хеши, выполняет код из нового root-owned снимка.
Установщик проверяет точные старые unit/config/install/notices-код,
активную известную службу без drop-ins, сохраняет и перечитывает приватные
резервные копии3изменяемых файлов. Останавливает только notifier, берёт
его lock, повторяет pins, меняет2пути Python в unit и2метаданных JSON,
перечитывает службу после daemon-reload/start и подтверждаетPID.
ExecStartPre проверяет чтение существующего bot token под UID1001 без
тестового сообщения. Служба сама отправляет настоящее уточнение при
изменившемся итоговом состоянии. Workers, квоты, финансовые данные,
счётчики попыток и таймеры не изменяются. Старые root-release не правятся.
Частичную установку не повторять; неизвестный результат отправки сохранить.
