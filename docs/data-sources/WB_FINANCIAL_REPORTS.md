# Единый вход: финансовые отчёты Wildberries

Для финансовых задач WB сначала определить кабинет/период/роль даты/показатель,
затем `msp-wb-report-guide route 'вопрос' --json` и нужное `field`/`formula`.

- [Полная логика](wb-financial-reports/GUIDE.md).
- [Точная карта колонок](wb-financial-reports/COLUMN_BINDINGS.md) и `field-bindings.json`.
- [Читатель/расчёты](wb-financial-reports/local_reports.py): `locate`, `summary`, `schema`, `inventory`.
- Навык: `msp-wb-financial-reports` для Hermes и Codex.
- Обычные заказы: [утверждённые отчёты](APPROVED_REPORTS.md), не финансовая детализация.

Проверено 10.11.2026: все 95 исходных колонок (+ _raw_json), шесть weekly-наборов,
три кабинета, точное соответствие официальной схеме WB. Установленные отчёты
читаются без root всеми локальными UID, без записи. Daily в эту приёмку не входят.
Полнота истории по списку документов — отдельный критерий от правильности колонок.

Общая точка для приложения: `/opt/mcp/data/wb-financial-reports/guide.py` и файлы
в этом каталоге; наличие/версию проверять по deployment.json. До создания этого
отдельного общего каталога администратором Hermes использует установленную копию
в проекте, но закрытый родитель проекта не позволяет читать её другому UID.
Инструкции не подключаются к произвольным приложениям автоматически: приложение
должно читать этот вход/JSON или импортировать local_reports.py. Контейнеру нужен
readonly-mount этих путей. Токены, API-вызовы и доступ к служебным журналам не нужны.
