# Отчёты, которыми можно пользоваться

Решение владельца 27–28.10.2026. Общие правила **всех** потребителей МСП:
Hermes, ChatGPT, самовыкупы, SIG-002 и аналитика. Не ограничивать одним чатом.

## Главный порядок поиска

1. Сначала проверить QRsite MCP по точным товару, площадке, кабинету и периоду.
2. Если нужного метода/периода/показателя там нет, использовать **конкретный
   утверждённый отчёт** `_01_заказы`, ID каталога
   `mp_customer_orders_daily_weekly_monthly`. Не искать случайные таблицы на Drive.
3. Точный Google Sheets ID и ссылка находятся только в приватном
   `msp-server-bridge/docs/data-sources/MARKETPLACE_ORDERS_SOURCE_PRIVATE.md`
   и `/home/hermes/.local/share/msp/approved-reports/registry.json` на сервере.
4. Доступ на сервере разрешён **служебному аккаунту**, проверен 28.10.2026
   чтением метаданных, заголовков и значений. Отказы 403/404 отдельного
   Google-коннектора ChatGPT **не проверяют серверный аккаунт**.
5. Потребитель без доступа к серверу/аккаунту сообщает
   `CURRENT_CONSUMER_ACCESS_NOT_VERIFIED`, а не «отчёта нет».

## Где брать показатели заказов

| Точная вкладка | Назначение |
|---|---|
| `заказы общие день` | Заказанные штуки по дням, всем площадкам/магазинам/карточкам |
| `заказы фбс день` | Заказанные штуки по дням, FBS |
| `заказы фбо день` | Заказанные штуки по дням, FBO |
| `заказы` | Месяцы и недели: `Заказы (шт)`, `Заказы (сумма)`, `Заказы (цена)` |
| `заказы 30 дней` | Скользящий итог и дневные даты за 30 дней |
| `заказы импорт` | Вспомогательные месячные/недельные агрегаты по складам: штуки и ₽ |

Проверенные месячные заголовки на 28.10.2026 — август, сентябрь, октябрь 2026;
они динамические. **Не зашивать номера колонок и месяцы.**
`Т`/`Т неделя` — текущая неделя; `П` — прошлая; `ПП` — две назад;
далее `ППП`, `ПППП`. Латинские T/P из переписки обозначают эти русские поля.
Фактические даты недель читать из отчёта, не из старой копии.
Часовой пояс источника — Europe/Moscow; текущие день/неделя/месяц неполные.

## Готовый доступ на сервере

```bash
python3 /home/hermes/.local/share/msp/approved-reports/report_catalog.py list
python3 /home/hermes/.local/share/msp/approved-reports/report_catalog.py guide --report orders
python3 /home/hermes/.local/share/msp/approved-reports/report_catalog.py read --report orders --sheet 'заказы 30 дней' --range A1:AI5
```

Команда читает только заранее зарегистрированный отчёт через существующую
readonly-аутентификацию. Ограничение — 10000 ячеек на запрос; большие чтения
делить на части. Никаких изменений исходных ячеек, прав доступа и служб.

SQL-инструкция: `/opt/mcp/data/msp/msp_report_catalog.sqlite3`.
Таблицы: `report_source`, `report_sheet`, `report_column`, `report_instruction`,
`report_guide`. Это **реестр и инструкция**, не выгрузка всех заказов:
`report_source.data_materialized=0`. Время проверки доступа не равно свежести данных.

```sql
SELECT report_id,title,access_method,verified_at_utc FROM report_source;
SELECT title,purpose,fulfillment,grain,metrics FROM report_sheet;
SELECT instruction FROM report_instruction ORDER BY rule_order;
SELECT title,column_letter,header FROM report_column
JOIN report_sheet USING(report_id,sheet_id) ORDER BY title,column_index;
```

Для чтения SQLite открывать URI с `mode=ro`; факты из Google получать командой
`read` по нужной вкладке. Локальный реестр не сканирует Google Drive.

## Как не исказить данные

- Ключ: площадка + магазин + числовой `market_article`; внутренний артикул отдельно.
  Имена и порядок первых колонок различаются между вкладками.
- Заказы в штуках — **заказанные единицы**, не число корзин и не оплаченные продажи.
  Сумма заказов в ₽ — не прибыль, выплаты или подтверждённая выручка.
  `Заказы (цена)` — агрегированная цена заказов, не текущая цена продавца.
- Производственные заказы не являются заказами покупателей.
- Общий итог, FBS, FBO, дни, недели и месяцы перекрываются. Не складывать их
  повторно; выбрать один источник/охват/период. FBO не означает расход FBS-склада.
- Пустые/ошибочные/отсутствующие значения не заменять нулём. В `заказы 30 дней`
  формулы скрывают нули пустым текстом: проверять первичный дневной ряд.
- Среднее за 30 дней: ровно 30 **завершённых** календарных дней, без сегодняшнего;
  сумму делить на 30, не на дни с заказами. Проверять присутствие всех дат.
- Агрегат не доказывает статусы отмен и идентичность самовыкупов. Без доказанного
  сопоставления не называть ряд «независимым/органическим спросом».
- `_N` сигнала не заменять произвольной оценкой. Достаточность производственной
  партии оценивать по проверенному расходу того же склада: одна штука не делает
  проблему решённой только потому, что её дата подходит. Нет достаточных данных — уточнить.
- Проверять даты/маркеры обновления конкретной вкладки. Время чтения и изменения
  файла не доказывает полноту загрузки. Сам отчёт только читать.

## Границы распространения

Правило действует для всего проекта, но доступ проверяется для каждого
потребителя. Локальная установка не сливает истории и не обновляет автоматически
уже открытые чаты: им нужно перечитать этот документ или SQL guide.
Публикация PR отдельно от main; проверка отдельного процесса на сервере
не является проверкой каждого внешнего ChatGPT-коннектора.
